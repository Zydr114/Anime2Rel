# Anime2Real 实施计划

> 版本：v1.0（2026-10-16） · 协议：AGPL-3.0-or-later · 验收人：项目维护者本人

## 0. 目标与参考效果

用户上传**真实背景照片**和**二次元立绘**，调整参数后在浏览器本地生成“溶图”（Anime in Real）。

风格参考为 `docs/example.png`，其中包含以下要素：

| 要素 | 示例中的表现 | 对应模块 |
| --- | --- | --- |
| 环境光一致 | 阴天漫射光，人物左上方有大面积高光，暗部偏冷 | 光源分析 + 立绘重光照 |
| 色彩统一 | 人物饱和度被压低，整体偏暖褐色 | 颜色匹配 + 全局调色 |
| 空间感 | 塔身轻微虚化，前景树木压暗 | 深度估计 + 景深 |
| 胶片质感 | 黑位压低、颗粒、左上角丁达尔光束 | 后处理 |

**功能范围**

- ✅ 背景深度估计与光源分析（用户可介入修正）
- ✅ 根据立绘位置自动调整光照和颜色
- ✅ 基于 Depth Anything + WebGPU 的深度估计与景深
- ✅ 基础图像调整（白平衡、曝光、颜色、饱和度等）
- ✅ 后处理（Bloom、胶片颗粒、混色等）
- ❌ 抠图：不提供抠图模型和抠图功能，立绘必须自带透明通道
- ❌ Demo 图像：暂不提供

所有计算都在浏览器本地完成，图片不会上传。站点为纯静态部署。

**数据约定**

- 内部统一使用**线性 sRGB 的 RGBA16F** 纹理，只在输出时编码回 sRGB。
- 预览时长边不超过 2048 px（可配置）；导出用原始分辨率，超过 GPU 纹理上限时分块渲染。
- 深度统一表示为归一化逆深度 `d ∈ [0,1]`，1 表示最近。通过可调映射 `z = 1 / (a·d + b)` 转成伪距离，供景深和点光源衰减使用。

## 3. 核心算法

### 3.1 深度估计（DepthWorker）

1. **背景**：把短边缩放到 518 px（patch size 14 的倍数），用 DA V2 推理得到相对逆深度，再按 1% / 99% 分位数归一化。
2. **立绘**：先把立绘合成到中性灰底上再推理，然后用 alpha 遮罩剔除灰底部分，得到立绘自身的相对起伏。
3. **边缘对齐上采样**：以全分辨率亮度为引导图，用 Fast Guided Filter（He & Sun 2015）把 518 px 的深度放大到工作分辨率，避免景深边缘出现锯齿和光晕。
4. **派生图**：
   - **天空遮罩**：取 d 接近 0、位于画面上部、纹理少的连通区域。
   - **法线图**：对多尺度平滑后的伪深度求 Sobel 梯度，`n = normalize(-k·∂z/∂x, -k·∂z/∂y, 1)`。同时输出置信度，深度不连续处和天空区域降权。
5. **调试视图**：提供深度、法线、天空遮罩三种视图。

### 3.2 光源估计（AnalysisWorker）：生成候选，由用户确认

输入为长边 512 px 的线性背景图、深度、法线和天空遮罩。下面四个估计器各自输出带置信度的候选，再统一融合。

| 估计器 | 方法 | 产出 | 适用场景 |
| --- | --- | --- | --- |
| A. 可见光源检测 | 对 log 亮度建高斯金字塔，在多尺度 DoG 上找局部极大值；对 L > max(P99.5, 0.9·Lmax) 的区域求连通域，并评估面积、紧致度、位于天空还是前景 | 屏幕位置；颜色（取过曝区外环像素）；大小 | 太阳、路灯、窗户、霓虹 |
| B. 球谐（SH）拟合 | 在非天空、法线置信度高的像素上，按 Lambert 假设拟合 2 阶 SH（9 个系数 × RGB）；用 IRLS/Huber 加权最小二乘压低反照率变化的干扰；L1 带的方向作为初值，再用“常数环境光 + 截断余弦方向光”模型在球面上搜索细化（画面法线只覆盖朝向相机的半球，L1 有约 10° 的系统偏差）；置信度 = 方向性（‖L1‖ / L0）× 法线覆盖度 × 拟合优度 | 3D 主光方向、主光强度、环境光（与主光联合拟合的分通道常数）、低频环境光照（供 §3.3 使用）；主光颜色投影到普朗克轨迹，只保留冷暖 | 光源在画面外；阴天 |
| C. 轮廓法（Nillius & Eklundh 2001；Lopez-Moreno et al. 2010） | 在深度不连续处取遮挡轮廓的前景一侧，此处法线落在像平面内；拟合 `I = a + b·(n·l₂D)` | 光在像平面内的方位角 | SH 结果模糊时作补充 |
| D. 天空梯度 | 统计天空区域亮度梯度的主方向 | 太阳的大致方位（可在画外） | 晴天、多云 |

**融合规则**

- C、D 只给出画面内的方位，借用 B 的前后分量（没有 B 时取固定值）补成 3D 方向。
- 方向相差小于 25° 的候选按置信度加权合并（合并后的置信度按“任一成立”累计），保留置信度最高的 3 个。光源强度由 B 的联合拟合给出。
- **阴天判定**：天空占比够大、天空不是夜空、天空亮度变化小、画面反差小、‖L1‖ / L0 小，五项各自打分后相乘。满足且画面里没有可见太阳时标记为“漫射主导”，主光设为来自上方的柔和天空光。
- **光源类型**：
  - 位于天空的候选视为**方向光**，方向是从相机穿过该像素的射线（默认 FOV 60°，可调）。
  - 画面内的灯具视为**点光源**，位置为 `(x, y, z(d))`。

**用户介入**

- 画布上为每个候选显示可拖动的 Gizmo，支持启用/禁用和删除，也可以点击画面添加光源。
- **光照方向球**：在球面上拖动设置方位角和仰角，支持背光（光源在人物后方）。
- 每个光源可调颜色（吸管取色或色温 K）、强度和软硬度。
- **灰球预览**：在立绘位置渲染一个灰色漫反射球，用当前环境光加所有光源照明，方便判断光照是否与背景一致。

M2 实现说明：自动分析在背景的深度结果就绪后进行（长边 512 px，约 0.5 s）；第一次分析的结果直接写入光源列表，“重新分析”会替换现有光源并可撤销。修改视场角后需要重新分析，候选方向才会按新视场角换算。环境光目前是常数（不随法线变化），完整的 SH 保留在分析结果里，M3 再决定是否使用。

### 3.3 立绘融合（随位置自动更新）

立绘的位置、缩放或深度发生变化时，重新计算三项：局部环境光、点光源方向与衰减、局部色彩统计。统计在 Worker 中对低分辨率数据进行，100 ms 防抖。

**(1) 颜色匹配**（`colorMatch` 节点）

1. **照明体适配**：用 Shades-of-Gray（p=6，排除过曝区和天空）或 Gray-Edge 估计背景白点，在 CAT16/Bradford LMS 空间做 von Kries 适配（D65 → 背景白点），强度可调。
2. **影调匹配**：在 Oklab 的 L 通道上，取立绘周围、深度相近的背景区域做加权统计，匹配 P1 / P50 / P99 三个分位点（单调曲线），让黑位和白位一致。
3. **色度匹配**：在 Oklab 的 a/b 通道上做 Reinhard 均值与方差迁移，可选 MKL（Pitié 2007）协方差迁移。提供“肤色保护”。
4. **饱和度收敛**：二次元原画通常比照片更饱和，因此把立绘 Oklch 色度的 P90 收敛到背景的对应分位。

**(2) 法线生成**（预计算后缓存为纹理）

`N = normalize(w₁·N_depth + w₂·N_inflate + w₃·N_detail)`，默认权重 0.5 / 0.4 / 0.1，作为高级参数开放。

- **`N_depth`**：由立绘的 DA V2 深度求得。
- **`N_inflate`**：对 alpha 做精确欧氏距离变换（Felzenszwalb–Huttenlocher），按枕形剖面 `h = r·√(1-(1-t)²)` 膨胀成高度场，再求法线。
- **`N_detail`**：对双边平滑后的亮度做小权重凹凸，并排除线稿，避免线条被浮雕化。

**(3) 增量重光照**（`relight` 节点）

原画本身已经画好了明暗，再整体打一次光会出现双重阴影，所以采用比值式重光照：

```
S(N)       = SH_bg(N)·k_amb·A_local + Σᵢ Cᵢ·Iᵢ·attenᵢ·diffuse(N·Lᵢ)
S_neutral  = 同一公式，光照替换为正面中性光
C_out      = C · lerp(1, S(N) / S_neutral, strength)
           + rim(N,V,L)·C_rim + spec(N,H)·C_spec
```

- **`diffuse` 风格**：写实（wrap Lambert）、柔和（half-Lambert）、赛璐璐（两阶 smoothstep，阈值和柔度可调）。
- **`rim`**：`pow(1 - N·V, p) · saturate(dot(N.xy, L.xy))`，光源在人物后方时自动增强，形成逆光轮廓光。
- **`A_local`**：在背景的大半径模糊 mip 上，按立绘所在位置采样。人物放进阴影区会自动变暗。
- **衰减**：点光源按 2.5D 距离衰减，方向光不衰减。
- **可选**：在立绘高度场上做屏幕空间 AO。

**(4) 边缘与质感融合**（`composite` 节点）

- **Light Wrap**：把模糊后的背景叠加到立绘边缘带（alpha 内缩得到）。
- **边缘软化**：按该深度处背景的清晰度，对 alpha 做 0.5–1 px 羽化。
- **噪声匹配**：在背景平坦区域，用拉普拉斯响应的 MAD 估计噪声 σ，给立绘补上等量噪声。
- **深度遮挡**（默认关闭）：比立绘更近的背景像素以软过渡遮挡立绘，并提供遮罩预览。

M3 实现说明（与上文不同的地方）：

- **统计调度**：没有用固定防抖，而是在计算期间又有变化时，算完后按最新状态再算一次。Worker 一次统计只需几毫秒，所以拖动过程中也会持续更新。立绘深度默认取 alpha 包围盒底边中点处的背景深度，也可以在“前后位置”中手动设置。
- **影调**：P1 和 P50 按强度匹配。P99 不去匹配背景，而是跟随中间调的曝光变化，因为立绘周围的背景里往往没有白色物体。两段斜率都限制在 0.4–2.5。明度变化时 a/b 等比缩放，饱和度保持不变。
- **色度**：Reinhard 均值迁移会把立绘的主色（比如大面积的蓝色衣服）当成色偏去掉，所以改为把周围背景的平均色度按强度叠加到立绘上（“环境色调”），暗部按明度减弱。方差部分交给饱和度收敛：P90 之比先按影调的中间调变化修正，缩放限制在 0.4–1.15。MKL 未实现。
- **重光照的分母**：`S_neutral` 改为当前光照在正面半球上的余弦加权平均 `S_ref`，在立绘中心处由 CPU 计算。这样整体明暗只由影调匹配决定，重光照只带来朝向造成的变化。比值限制在 0–4。环境光使用分析得到的完整二阶 SH，再乘以环境光倍率。
- **`A_local`**：改为“直射光可见度”，取立绘周围与整张背景（非天空）平均亮度之比的平方根，限制在 0.4–1.3，乘在所有光源上。人物站进阴影后直射光变弱、明暗变平；整体变暗交给影调匹配，避免两处重复压暗。
- **轮廓光**：取 `pow(1 − N.z, 2)` 与剪影边缘带两者的较大值，再乘以“朝向光源一侧”和 `saturate(0.3 − 0.7·L.z)`，所以正面光没有轮廓光。边缘带宽度为立绘长边的 2%，由 alpha 的 mip 模糊得到；线稿不参与。混合后的法线在轮廓处往往不够贴近像平面，只靠法线时轮廓光几乎看不出来。
- **高光**：Blinn-Phong，默认强度为 0。屏幕空间 AO 未做。
- **Light Wrap**：边缘带 = alpha × (1 − mip 模糊后的 alpha)，平方后与 mip 模糊后的背景做滤色混合。线稿只保留 30% 的效果，避免描边发灰。
- **边缘软化**：按固定的像素数做十字五点羽化，只作用于 alpha 有变化的地方；暂不按背景清晰度自适应。
- **噪声**：在背景原分辨率上均匀取 4×4 个小块，分别估计后取中位数。在 sRGB 编码空间加三角分布噪声；预览按渲染分辨率缩小 σ。
- **前后对比**只影响预览，导出始终使用融合结果。**深度遮挡**推迟到 M4，与深度合成一起实现。
- **验收结论**（2026-10-18）：算法基本正常工作，默认参数偏保守。光源估计结合各项参数已能调出较好的光照；不存在能适用于所有素材的默认值，默认值保持保守，由用户按素材调节。

### 3.4 深度合成与景深

- **立绘深度** = 放置深度 `z_c` + 立绘自身起伏 × 厚度。`z_c` 默认取背景在立绘 alpha 包围盒底部中点处的深度，代表立绘所站的地面；用户可用“前后位置”滑块调整。
- **对焦**：点击画面即对焦到该点的深度，默认对焦在立绘上。可调参数有光圈、焦外过渡和散景形状。
- **实现分两步**：
  1. **基线**：把合成深度转成 viewZ，交给 three.js `DepthOfFieldNode`。
  2. **目标方案：分层 DOF**。背景按自身的弥散圆（CoC）做深度感知 gather 模糊，近景场和远景场分开处理（参考 Jimenez 2014）；立绘层按自己的 CoC 单独模糊；最后再合成，以消除立绘边缘的光晕和渗色。

M4 实现说明（与上文不同的地方）：

- **跳过基线**：按维护者的决定，没有接入 three.js `DepthOfFieldNode`，直接实现分层 DOF。景深默认开启，光圈较小，对焦在立绘上。
- **弥散圆**：CoC = 光圈 × max(|d − d_focus| − 合焦范围, 0) × 图像长边，d 为归一化逆深度，正值表示近景。薄透镜模型下弥散圆与逆深度差成正比；DA V2 输出的是仿射不变的逆深度，尺度可以并入光圈，偏移在相减时抵消，所以可以直接使用。光圈按“弥散圆相对图像长边”的百分比表示，默认 1%；合焦范围默认 3%。
- **立绘深度**：先把放置深度换算成伪深度 `z_c = 1/(d + 0.1)`，立绘某处的伪深度为 `z_c − (r − r_ref) × scale`，再换回逆深度。r 是立绘自身的深度估计，r_ref 是立绘不透明区域的深度中位数（融合 Worker 计算），所以中位数处正好在放置深度上；`scale = 厚度 × 立绘高度 × z_c / f`，厚度按立绘高度的比例给出，默认 15%。
- **对焦**：自动模式对焦在立绘的放置深度上，焦点标记画在立绘不透明区域的中心。在画布上点到立绘的不透明处时，对焦到立绘该处的起伏深度；点到其他地方时，对焦到背景该点的深度。背景上的对焦点随背景尺寸缩放，更换立绘时立绘上的对焦点恢复为自动。
- **gather**：没有完整实现 Jimenez 2014 的近景场、远景场拆分，改用 Gustafsson《Bokeh depth of field in a single pass》式的单次 gather：
  - 48 个 Vogel 螺旋采样点，可映射为五、六、八边形散景，权重按半径的平方修正。
  - 样本的弥散圆覆盖到当前像素才计入。比当前像素远的样本，弥散圆最多按当前像素的两倍计算，所以模糊的远景不会盖住清晰的近景，模糊的近景可以扩散到清晰的远景上。
  - 采样半径取当前像素所在 16×16 块及周围 3×3 块中弥散圆的最大值；按采样间距选 mip 层级，先做预模糊。
  - 背景层、立绘层、遮挡层各自 gather 后再合成。背景层不包含立绘，立绘层不会采到背景颜色，因此立绘边缘没有光晕和渗色。
- **深度遮挡**（默认关闭）：
  - 遮罩 `m = smoothstep(容差 − 过渡/2, 容差 + 过渡/2, d_bg − d_char)`，在整个立绘矩形内连续计算，透明处按立绘平面的深度算。这样剪影边缘不会因为遮罩被截断而透出立绘的轮廓。
  - 遮挡层 = 背景 × m，按背景的弥散圆模糊，至少做 1 px 模糊用于抗锯齿。
  - 三种方式：
    - **不透明**（默认）：遮挡层直接盖在最上面。
    - **变暗**：在立绘像素上按亮度取较暗的一个，适合树叶、栏杆等细碎的暗色遮挡物；立绘中比遮挡物更暗的部分（如线稿）会透出来，面板中有提示。
    - **正片叠底**：遮挡层与立绘相乘。
  - 遮罩预览只在景深步骤显示。
- **前后对比**改为对比“直接贴上去”（不做融合、景深和遮挡）与当前结果，只影响预览。法线视图同样跳过景深和遮挡。调试视图新增“景深”：合焦处为灰度，近景染蓝、远景染橙。
- **缓存**：背景预处理、块统计和背景景深只在背景、深度、对焦参数或对比状态变化时重绘，拖动立绘时只重绘立绘相关的图层和合成。M3 的拖动测试中步进间隔仍为 17 ms。
- **导出**：以背景原分辨率分配全部图层，最多 7 张全尺寸半浮点渲染目标，其中 3 张带 mipmap。超大图的显存压力留给 M6 的分块导出解决（已实现，见 §5）。
- **验收结论**（2026-10-18）：景深部分通过。遮挡按下面的扩展方案实现后重新验收。

M4 遮挡扩展（2026-10-18 与维护者确定）：

- **接地点**：自动估计取立绘不透明区域包围盒底边的中点，但裙摆、披风、特效、坐姿、站在水中等情况下这一点不是脚。现在由用户在画布上拖动接地点，接地点记录在立绘自身的坐标中，可恢复自动。立绘深度改为取接地点附近一小块背景深度的中位数。站在水中时把接地点放在水线处：深度取水线处的水面深度，水位线就是过接地点的水平线（接地点与水位线合并为一个控件）。
- **站立阴影**：
  - **接触阴影**：以接地点为中心的柔和椭圆，宽度取接地点上方立绘的不透明宽度（双脚的跨度），扁度按接地点处的地面朝向估计。
  - **平面投影**：把立绘当作立在接地点上、朝向光源的竖直平面，沿主光源方向投到地面平面上。地面平面由接地点的深度和法线确定，影子长度随光源仰角变化，离脚越远越模糊。
  - 两种阴影都画在背景上，只落在与地面平面深度一致的地方，跟背景一起参与景深。阴影颜色按环境光与直射光之比估计，晴天偏天空色，阴天投影自然消失。立绘底部被裁切（半身像）且接地点为自动时不画阴影。
  - 屏幕空间投影（落在台阶、墙面等不平的表面上）仍在 M8。
- **透明介质与水体**：新增两种遮挡方式。
  - **透明介质**：用于雾、玻璃、薄纱等。按深度对比判断遮挡，结果 = 立绘 × 透过率 + 介质颜色 × (1 − 透过率) + 背景的高频细节；透过率随深度差按指数衰减（Beer–Lambert，即水体着色器中的 depth fade）。介质颜色默认取模糊后的背景。
  - **水体**：水位线以下算作水中，透过率随水下距离衰减；另有水线高光（带波纹起伏的亮边）和折射扰动（水下部分随波纹轻微扭曲）。倒影放到 M8。
- **多区域遮挡**：遮挡物属于背景，所以遮挡区域在背景上划定，不从遮罩中自动拆分（自动拆分的区域在移动立绘时会变化，也不对应物体）。用画笔粗略涂出区域，再用引导滤波吸附到背景的边缘；精确的遮挡边界仍由深度对比决定。最多 4 个区域，每个区域选择自己的遮挡方式和参数，没涂到的地方使用默认方式。笔触以矢量形式记录在文档中，可撤销。

M4 遮挡扩展实现说明（与上文不同的地方）：

- **接地点**：
  - 立绘步骤和景深步骤的画布上都有接地点标记（立绘脚下的短横线和三角）。拖动后变为手动，双击标记或面板中的“恢复自动”回到自动。
  - 接地点按立绘 UV 记录，随立绘移动、缩放、旋转、翻转。
  - 自动模式仍取不透明包围盒底边的中点。
  - 立绘深度取接地点附近一小块背景深度的中位数。
- **站立阴影**（立绘步骤“站立阴影”分组；默认接触阴影 50%、投影 60%）：
  - **地面平面**：过接地点的 2.5D 位置，法线固定为竖直向上，即假设相机水平。没有按计划用接地点处的深度法线：DA V2 的仿射不变深度换成伪深度后，平地的法线明显前倾，光源仰角会被算得很低（合成场景中晴天的 sin 仰角只有约 0.05），投影几乎看不见。
  - **接触阴影**：椭圆宽度取接地点以上包围盒高度 6% 范围内的不透明宽度（双脚的跨度），扁度取视线与地面法线夹角的余弦，限制在 0.1–0.6。
  - **投影**：把立绘当作立在接地点上、朝向光源的竖直平面。地面上沿背离光源方向距接地点 s 处，对应立绘上高 s·tan(仰角) 的位置。离脚越远，按距离取立绘更粗的 mip 层级，影子越模糊。仰角 sin 低于 0.15 时逐渐淡出。
  - **阴影颜色**：挡住主光源（地面上贡献最大的光源）后的光照与全部光照之比，最暗不低于原亮度的 20%。接触阴影在此基础上再遮住 55% 的环境光。
  - **作用范围**：阴影只落在背景深度与地面平面接近的地方，相对深度差 20%–45% 之间逐渐消失，天空上不画。阴影作为乘数图作用在背景上，按背景的弥散圆一起模糊。
  - **不画阴影的情况**：接地点为自动、不透明区域贴着立绘底边、且最下方 1% 的行平均覆盖率超过 45% 时，视为半身像。水体遮挡开启时接地点是水线，同样不画。
- **遮挡方式**：
  - 介质和水体的遮挡强度写在立绘深度图的 g 通道里，合成时与不透明方式一样覆盖立绘，即 遮挡层 + 立绘 × (1 − 遮挡强度)，再叠加背景的高频细节（预处理背景 mip 0 与 mip 2.5 之差）。
  - **透明介质**：遮挡强度 = 在后方 × (1 − 清澈度 × e^(−浑浊度 × 10 × max(Δ − 容差, 0)))，Δ 为背景与立绘的归一化逆深度差。
  - **水体**：遮挡强度 = 在水线下 × (1 − 清澈度 × e^(−浑浊度 × 20 × h / 立绘高度))，h 为水线以下的距离。水体与深度无关，水线是过接地点的水平线，水线随波纹起伏，水线处有一条高光。水下的立绘按波纹偏移采样，形成折射扰动。
  - 新增 **不遮挡** 方式。用于区域时可以排除深度估计出错的地方；用于区域外（默认方式）时，只在画出的区域内遮挡。
  - 选择水体时，画布上画出横跨立绘的水线（浅蓝色虚线）。
- **多区域遮挡**：
  - 面板中的“区域外的遮挡方式”是默认方式，区域列表最多 4 个。选中区域时画布上显示画笔，各区域按颜色着色，正在编辑的区域颜色更深。画笔和橡皮擦的大小按屏幕像素计，一笔一次撤销。
  - 后画的区域覆盖先画的：第 k 个区域的权重 = r_k × Π_{j>k}(1 − r_j)，区域外的权重 = Π(1 − r_j)。合成时每种方式各自计算后按权重混合，变暗、正片叠底单独混合。
  - 笔画按文档坐标记录，更换尺寸不同的背景时按比例缩放。遮罩在不超过 1024 px 的背景缩小图上栅格化，打包成一张 RGBA8 纹理。
  - **边缘吸附**（默认开启，可关闭）：单纯的引导滤波只能柔化边缘，笔画画出界几个像素时移不回背景的边缘。实际做法：
    1. 把笔画边缘两侧各半个笔画半径（2–16 px）的带状区域视为不确定。
    2. 带内每个像素按颜色更接近附近笔画内侧还是外侧的平均颜色归属；内外颜色相近（附近没有边缘）时保持笔画原样。
    3. 最后用半径 2 的彩色引导滤波去噪并保留边缘的过渡。
- **渲染**：WebGPU 每个着色阶段最多 16 张采样纹理，加入阴影和区域纹理后合成着色器超出限制。预览时先把合成结果画到一张渲染目标，再由单独的显示 pass 叠加调试视图、遮罩预览和灰球；导出直接输出合成结果。
- **已知问题**：
  - 每画完一笔，主线程会卡顿约 150 ms（栅格化、吸附和上传）。每张背景第一次吸附时还要多算约 66 ms 的引导图统计量。切换边缘吸附开关会重算全部区域。
  - 投影按乘法压暗背景，落在背景原有阴影里时会重复变暗。
  - 地面平面假设相机水平，俯拍、仰拍明显时影子方向和长度会有偏差。
  - 接触阴影的默认值偏保守，浅色地面上可能需要调高。
- **验收结论**（2026-10-18）：遮挡扩展通过。性能无问题，水体、接触阴影工作正常。M4 完成，进入 M5。

| 色调映射 | AgX / Khronos PBR Neutral，可关闭 |
| 输出 | 8-bit 导出时加蓝噪声抖动，防止色带 |

**预设**：参数树的 JSON 快照，支持导入和导出。首批四个：阴天胶片（参照示例风格）、黄昏逆光、夜景霓虹、日系清新。

M5 实现方案（2026-10-18 与维护者确定）：

- **三级的分工**：
  - 背景层调整只改背景。立绘的颜色匹配仍按原始照片计算，所以压暗背景可以突出人物；想让两者一起变就用全局调整。
  - 立绘层调整加在融合结果之上。
  - 全局调整作用于合成结果。
- **前后对比**：调色、后期步骤中对比“调色前”（保留融合、景深、遮挡，去掉三级调整、全局调色和后期）与当前结果。其他步骤仍对比“直接贴上去”。
- **预设**：包含三级调整、全局调色和后期的全部参数。套用预设是一次撤销记录。导出的 JSON 内嵌 LUT 数据，可以单独分享。
- **默认值**：全部参数默认中性，色调映射默认关闭，不改参数时输出与 M4 完全一致。背景照片本身已经是显示用的图像，套用 AgX 等色调映射会改变原图的观感，所以只在预设或用户开启时使用。
- **管线**：背景层调整 → 分层景深与遮挡（立绘层调整位于融合之后、立绘景深之前）→ 合成 → 全局基础调整 → 色差 → Bloom、Halation、光束（线性 HDR）→ 暗角 → 色调映射 → 色轮、分离色调、LUT、混色（显示空间）→ 颗粒 → sRGB 编码与蓝噪声抖动。
- **与分辨率无关**：模糊半径、颗粒尺寸、色差、光束长度等都按图像长边的比例定义，预览与导出的观感一致。three.js 的 `BloomNode` 固定使用 5 级 mip，导出大图时光晕范围相对画面会变小，所以改用自己的 mip 金字塔，级数随分辨率变化。
- **局部色调**：高光、阴影和清晰度以对数亮度的快速引导滤波（He & Sun 2015，在 mip 上做盒式均值）为基底，在边缘处不产生光晕。

M5 实现说明（与上文不同的地方）：

- **页面**：调色步骤分为“基础调整”“色彩风格”“预设”三页，基础调整页顶部切换全局、背景、立绘三级；后期步骤是单独的一页。各页都有重置按钮。
- **基础调整**：
  - **顺序**：白平衡与曝光 →（局部：高光、阴影、清晰度）→ 对比度 → 白色、黑色 → HSL → 自然饱和度 → 饱和度 → 曲线 →（局部：锐化）。着色器和 `src/grade/color.ts` 的逐像素版本使用同一组公式和常数，后者用于单元测试。
  - **色温、色调**：参考白点是普朗克轨迹上的 6504 K，两者为 0 时矩阵为单位阵。色温满格为 ±100 mired（+1 约 3940 K，−1 约 18600 K）；色调沿轨迹法线偏移，满格为 0.02（CIE 1960 uv）。
  - **对比度**：在 log2 空间以 18% 中灰为支点，做端点固定的三次 S 形。白点为线性 1.0，黑点在中灰以下 8 档，满格系数 0.5，曲线保持单调。
  - **白色、黑色**：在 sRGB 编码值上分别平移亮部（0.5–1）和暗部（0–0.5），满格为 ±0.2、±0.1。计划中的“局部色调曲线”只用于高光和阴影。
  - **HSL**：8 个色相段的中心取红、橙、黄、绿、青、蓝、紫、品红纯色的 Oklch 色相，相邻段之间平滑过渡。色相满格 ±30°，明度满格 ±30%，接近灰色的颜色不调明度。自然饱和度对低色度的颜色作用更强，并对 Oklch 色相 55° 附近的肤色减弱 70%。
  - **曲线**：在编码值上计算，主曲线先于单通道曲线；单调三次样条烘焙成 256 点的查找表，超出 1 的值按末端斜率延伸。
  - **局部调整**：
    - 先把这一级的输入画成 log2 亮度的 mip 金字塔，再在 1/4 分辨率上算两个尺度的快速引导滤波系数。高光、阴影的基底半径为长边的 1/24、ε = 0.25，清晰度为 1/96、ε = 0.12。
    - 高光、阴影平移基底，满格分别为 1 档和 2 档；清晰度放大中尺度细节，中间调全强度；锐化是半径为长边 1/2000（至少 1 px）的亮度 USM。
    - 三级依次渲染，共用这两张纹理；没有局部调整时不分配、不计算。立绘层按不透明度加权，透明处退化为逐像素调整。
- **色彩风格**：
  - **色轮**：在编码值上逐通道计算 e' = (gain · (e + lift · (1 − e)))^(1/gamma)。每个色轮的亮度给出三个通道相同的分量；偏色方向取该 Oklch 色相在编码值空间中亮度为 0 的方向。
  - **分离色调**：在 Oklab 中按亮度给暗部、亮部加上 (a, b) 偏移，不改变亮度。满格色度为 0.06，过渡半宽 0.3，平衡满格时过渡中心移动 0.25。L < 0.15 时暗部色调逐渐减弱，纯黑保持中性。
  - **LUT**：没有用 `Lut3DNode`，在终处理 pass 中用半精度三维纹理按 sRGB 编码值查表，超出定义域的值被裁剪。一维 LUT 展开为 33³，三维 LUT 的边长上限为 129。LUT 数据按内容哈希登记在内存中，文档只保存 id、文件名和强度。
  - **混色层**：最多 4 层，可上下移动；纯色，或按底图亮度取色的 2–3 色渐变映射。实现了 W3C Compositing and Blending Level 1 的全部 16 种混合模式（计划列出 8 种），在编码值上计算。亮度蒙版的边缘柔化半宽为 0.1。
- **后期**（不使用 three.js 的 `BloomNode`、`radialBlur` 和 `ChromaticAberrationNode`）：
  - **Bloom 与 Halation**：
    - 共用一套 8 级 mip 金字塔。第 0 级长边固定为 1024 px，各级尺寸只由画面比例决定，所以预览和导出的光晕范围相同。
    - 预滤波用 Jimenez 2014 的 13 点降采样。Bloom 对最大通道取软阈值，Halation 对亮度取阈值，结果存在 alpha 通道。
    - 上采样为 up_k = mix(d_k, tent(up_{k+1}), 散射)，半径换算为散射 0.4–0.95。
    - Halation 在第 0 级只保留扩散到亮部外侧的部分（tent − 原值），所以红晕只出现在高光边缘，不会把整片高光染色。
  - **丁达尔光束**：
    - 遮罩 = 亮度软阈值 × 天空权重 × (1 − 立绘不透明度) × 1/(1 + (d/0.3)²)，d 为到光源的距离。天空权重在有深度、且开启“只让天空发光”时取天空遮罩，否则为 1。
    - 向光源方向做 3 次、每次 8 个样本的径向模糊。样本间距按指数分布，每次放大 8 倍；贡献随距离按指数衰减。光束长度按长边的比例定义。
    - 光源默认自动选择：优先方向光，其次按强度，跳过在相机后方的光源；也可以手动指定。没有可用光源时光束不生效，面板中给出提示。
  - **色差**：红、蓝通道按到画面中心的距离向相反方向缩放，满格时边缘处相差 ±1.5%。7 个采样从蓝到红平滑过渡，每个通道的权重之和为 1，不会出现分离的三重影。
  - **暗角**：曝光乘以 2^(档数 × smoothstep(内, 外, r))，r 以画面角落为 1；满格 ±2 档，负值压暗，正值提亮。中点和羽化决定内外半径。
  - **颗粒**：
    - 按长边比例划分网格，格子为长边的 1/3000–1/500。每个格点三个通道各取一个随机数，格点之间平滑插值，并按方差归一化，彩色程度在单色和三通道独立之间混合。
    - 颗粒加在编码值上，中间调最强，暗部和亮部为 35%。
    - 网格由文档坐标决定，预览与导出的颗粒图案一致，导出大图时颗粒随画面一起放大。颗粒小于一个像素时按尺寸减弱，使缩小的预览与导出图缩小后的观感一致。
  - **色调映射**：使用 three.js 的 AgX 和 Khronos PBR Neutral，默认关闭。
  - **抖动**：没有用蓝噪声纹理，改用 R2 低差异序列，在编码值上加 ±0.5 LSB 的抖动，预览与导出都有。只在有调色或后期参数生效时开启，所以不改参数时输出与 M4 一致。
- **预设**：
  - 在调色步骤的“预设”页，包括四个内置预设、本次会话中导入的预设、预设文件的导入导出，以及“清除调色与后期”。与当前参数一致的预设显示为选中。
  - 内置预设只调整全局一级。“阴天胶片”参照 `docs/example.png` 的风格：暖褐色调，绿色压暗并偏红褐，黑位压低，亮部略收，带颗粒和暗角。
  - 套用预设时替换三级调整、色彩风格和后期参数，是一次撤销记录。光束的光源与画面有关，不随预设保存，套用时保留当前的选择。
  - 预设文件是 JSON，使用中的 LUT 以 base64（float32，小端）内嵌，导入时重新登记。导入的内容逐字段检查类型并限制在界面允许的范围内，缺少或无效的字段取默认值，内置预设也经过同样的处理。导入的预设保存在浏览器本地（IndexedDB，M6 实现）。
- **渲染**：
  - 全局调整之后是一个终处理 pass，依次做色差 → Bloom、Halation → 光束 → 暗角 → 色调映射 → 色彩风格 → 颗粒。Bloom 和光束只在强度大于 0 时渲染。
  - TSL 的 `select` 会生成 if/else，两个分支共用的子表达式只在第一个分支里构建，另一个分支会读到未初始化的变量，导致画面全黑。终处理 pass 因此改用 `Fn` + `If` 组织，代码中有注释说明。
- **已知问题**：
  - Neutral 色调映射的趾部会把很暗的颜色压黑，并加重暗部的偏色。这是 Khronos PBR Neutral 本身的设计，夜景照片上很明显。内置预设都没有开启色调映射。
  - 光束只支持一个光源。
  - 抖动用的是 R2 序列，是蓝噪声的近似，极平滑的渐变上仍可能看到很弱的规则纹理。
  - 内置预设只在程序生成的场景上调过，在真实照片上的效果需要维护者验收时评估。
- **验收结论**（2026-10-19）：通过。维护者测试后认为效果很好，暂无需要改进的地方。M5 完成。

#### M8.1 边缘与光源易用性

**(1) 白边**

2026-10-19 用程序生成的立绘复现，原因有两个：

- **轮廓光**：边缘带宽度固定为立绘长边的 2%。立绘显示得很小时（例如高 200 px，带宽约 4 px），这条亮边相对头部、手臂等细部太粗，逆光时整圈发亮，看起来像白边。关闭 Light Wrap 后白边仍在，关闭轮廓光后消失。
- **抠图残留的底色**：很多抠图工具让半透明的边缘像素保留原背景（常见为白色）的颜色。低分辨率立绘被放大时，这一圈被放宽，关闭融合、直接贴上去时也能看到。现在的融合不会去掉它。

修复：

- **轮廓光宽度随局部粗细变化**：
  - 在 Worker 中对 alpha 做距离变换，得到每处形状的局部半宽（头发丝、手指细，躯干粗），烘焙成纹理。
  - 边缘带宽度取“长边的 2%”与“局部半宽的一定比例”中较小的一个。比例在开发时按效果确定。
  - 同时检查小尺寸时的亮度，避免轮廓光饱和成白色。
  - 大尺寸立绘的观感应与之前接近。
- **去除边缘残留的底色**（默认开启，可关闭）：
  - 导入立绘时，对半透明像素估计真正的前景颜色，替换掉混入的底色。算法为快速多级前景估计（Germer et al. 2020，pymatting 使用的方法）：已知 alpha，把像素颜色看作前景色与未知背景色按 alpha 的混合，在多级分辨率上求平滑的前景色和背景色。
  - 边缘干净的立绘经过处理后几乎不变，所以默认开启。这是本阶段唯一会改变旧工程观感的地方。
  - 在 Worker 中计算，结果按立绘缓存，不保存进工程文件（打开工程后重新计算）。
- **边缘收缩**：新增滑块 0–2 px（按文档像素计，与边缘羽化一致），把 alpha 向内收缩，作为残留底色较宽时的保底手段。默认 0。

**(2) 轮廓光束**

- 逆光时，让光束从人物被轮廓光照亮的边缘向外放射。
- 后期步骤“丁达尔光束”分组新增“轮廓光束”强度，默认 0。它与现有光束共用光源、长度和径向模糊，只是在光束遮罩中加入轮廓光的亮度。
- 融合 pass 额外输出轮廓光的亮度，用多渲染目标或单独的轻量 pass，开发时按性能选择。
- 导出大图时与现有光束一样，在预览分辨率上渲染后按输出坐标采样。

**(3) 光源易用性**

- **类型改名**，配上图标和一句说明：
  - 方向光改为“太阳 / 天光”：远处光源，只有方向，不随距离变暗。
  - 点光源改为“灯”：近处光源，有位置，离得越远越暗。
  - 内部类型不变。
- **自动分析**：
  - 光源列表中不再显示估计器字母（A/B/C/D），改为“自动识别”或“手动添加”，置信度显示为高、中、低。
  - 估计器的逐项报告收进折叠的“分析详情”。
- **首次使用提示**：光源步骤顶部加一段说明，介绍两种光源和光照方向球的用法。可以关闭，关闭状态保存在浏览器本地。

M8.1 实现说明（与上文不同的地方）：

- **轮廓光宽度**：
  - Worker 在引导分辨率（长边不超过 1024 px）上计算边缘带，与线稿遮罩、到剪影边缘的距离一起烘焙成一张纹理。
  - 边缘带从外描边的内侧算起，不从 alpha 边缘算起：轮廓光照亮描边里面的颜色，描边本身保持深色。为此，线稿检测只和不透明的邻域比较，紧贴透明区域的外描边也能识别出来。
  - 宽度取“长边的 2%”与“局部半宽的 20%”中较小的一个。局部半宽按圆盘包含（形状内能放下的最大圆）在不超过 512 px 的网格上计算，再平滑。
  - 立绘显示得很小、一个屏幕像素盖住多个引导像素时，最外一个像素不加轮廓光，保留描边或剪影本身的颜色。
  - 亮度软限制：超过立绘本身亮度（不低于中间调）的 1.5 倍后平滑压缩，最多到 3 倍。一般强度下不变。
- **去除残留的底色**：
  - 在 sRGB 编码值上求解：抠图工具一般在编码值上估计 alpha、混合颜色。完全透明的像素颜色没有意义（浏览器解码时预乘后为黑色），不参与数据项。
  - Worker 在引导分辨率上求出前景色和背景色；着色器在原分辨率上把放大后的结果作为邻域值，逐像素再解一次 2×2 方程，保留细节。不透明的像素保持原色。
  - 与“直接贴上去”对比时，立绘显示原来的边缘。
- **边缘收缩**：在收缩半径上取 8 个方向 alpha 的最小值，按它与原 alpha 之比缩小像素。
- **轮廓光束**：
  - 用单独的 pass：融合节点只输出轮廓光一项，在光束的分辨率（长边 1024 px）上渲染，只有轮廓光束强度大于 0 时才渲染。TSL 只编译轮廓光依赖的节点，比完整的融合 pass 轻。
  - 光束遮罩 = 原有遮罩 × 强度 + 轮廓光 × 轮廓光束强度 × 32。轮廓光部分不受阈值、到光源的距离和“只让天空发光”的影响。轮廓光只是一条窄带，径向模糊是沿光线取平均，被稀释得很弱，所以倍数较大。
  - 光束的亮度随立绘的轮廓光强度变化。“立绘”步骤中的轮廓光为 0 时，面板给出提示。
- **光源易用性**：
  - 列表中自动识别的光源显示“自动识别 · 置信度高 / 中 / 低”，置信度不低于 0.6 为高，不低于 0.3 为中。“分析详情”中列出每个自动识别的光源的依据和置信度数值；估计器改用中文名称：画面中的光源（A）、明暗分布（B）、物体轮廓（C）、天空亮度变化（D）。
  - 选中的光源下方显示类型说明。顶部的说明关闭后记在浏览器本地（`a2r.ui.dismissedHints`）。
- **已知问题**：
  - 轮廓光束不考虑遮挡：立绘被前景挡住的部分仍会发出光束。
  - 轮廓光束的亮度随边缘带宽度变化，立绘显示得很小时较弱。
  - 残留底色按平滑变化的背景估计。抠图前的背景纹理复杂时，可能仍有残留，可以配合边缘收缩使用。
- **验收结论**（2026-10-19）：通过，没有需要修改的地方。

#### M8.2 镜头光晕

- **原理**：
  - 光源在画面上的位置为 L，画面中心为 C。光晕元素排在 L 与 C 的连线上，位置为 L + (C − L)·k：k = 0 在光源处，k = 1 在画面中心，k > 1 越过中心到另一侧。
  - 光源移动时，整串元素一起绕画面中心移动。
- **元素类型**：
  - 光辉：光源处的径向辉光；
  - 光环；
  - 星芒：多条长短不一的射线；
  - 横向拉丝：变形宽银幕镜头的水平光条；
  - 鬼影：圆形或多边形光斑，边数可以跟随“景深”中的光圈叶片数；
  - 彩虹环：按波长着色的环；
  - 闪点。
- **元素参数**：位置 k、大小（相对画面长边）、颜色、强度、旋转、柔和度，以及鬼影的边数、彩虹环的色散。
- **渲染**：
  - 所有元素按公式逐像素计算，不使用贴图。
  - 以加法叠加在线性 HDR 中，位于 Bloom、Halation、光束之后，暗角和色调映射之前。
  - 元素都是解析计算的，分块导出没有接缝，与预览一致。
- **可见度**：在光源位置周围的一小片区域内取样，按被遮挡的比例减弱整串光晕。
  - 被立绘遮挡时减弱。
  - 方向光（太阳）落在非天空处，例如被建筑挡住时，视为被遮挡。
  - 光源移出画面后按距离淡出。
- **光源选择**：与丁达尔光束相同，默认自动选择（优先方向光，跳过相机后方的光源），也可以手动指定。只有在画面内或画面附近的光源才产生光晕，面板中说明这一点。
- **预设与编辑器**（后期步骤新增“镜头光晕”分组）：
  - 分组中有开关、整体强度、整体大小、光源选择和预设列表。
  - 内置 4–6 个预设，例如柔和太阳、蓝色拉丝、复古鬼影、强星芒。
  - 元素列表最多 16 个，可以添加、复制、删除、上下移动。选中元素后显示它的参数，交互与混色层一致。
  - 编辑后的光晕可以存为自定义光晕，保存在浏览器本地，也随工程文件和调色预设保存。
- **版权**：只借鉴 Optical Flares（Video Copilot 的商业插件）的元素构成方式，不导入、不内置它的预设和贴图，所有元素由程序生成。镜头污渍贴图暂不做。

M8.2 实现说明（与上文不同的地方）：

- **元素公式**（坐标以元素半径为单位，r 为到元素中心的距离，θ 为方位角减去旋转）：
  - 光辉：1 / (1 + (r / a)²) · (1 − r)²，a 随柔和度在 0.05–0.5 之间。
  - 光环、彩虹环：以 r = 1 为中心的高斯环带，宽度随柔和度变化。彩虹环在环带内按色相从紫到红着色，按色散与白色混合。
  - 星芒：射线数为 n，每条射线的长度由随机种子决定，在长度内线性收窄；用到最近射线的垂直距离计算，射线宽度不随距离变宽。
  - 横向拉丝：沿旋转方向的细长光条，横向按指数衰减，纵向从中心向两端渐隐。
  - 鬼影：圆形或正多边形，边缘按柔和度过渡，边缘比中心略亮。边数跟随光圈时，取“景深”中的叶片数和旋转角；叶片数为 0（圆形光圈）时是圆形。
  - 闪点：半径内随机分布的十字小星，位置、大小、亮度由种子决定。
  - 只计算元素半径 1.2 倍以内的像素。所有元素都是解析计算，分块导出与整幅导出逐像素一致。
- **参数传递**：每个元素 4 个 vec4，16 个元素放在一个 uniform 数组里；终处理 pass 用循环按实际个数计算，不为每个元素展开着色器。
- **可见度**：
  - 在光源周围半径为长边 1.2% 的圆盘内取 24 个点，被遮挡的比例越大越暗。画面外的采样点不计。
  - 遮挡取立绘的 alpha；光源是太阳 / 天光且有深度结果时，还取 1 − 天空遮罩。
  - 结果渲染到 1×1 的目标，终处理 pass 读取。分块导出时沿用整幅代理渲染的结果。
- **淡出**：光源到画面边缘的距离从 0 增加到长边的 20% 时，光晕按 smoothstep 淡出。
- **整体参数**：整体强度 50% 时为元素本身的强度，100% 时为 2 倍；整体大小 50% 时为元素本身的大小，范围为 0.5–2 倍。
- **预设与保存**：
  - 内置五组光晕：柔和太阳、蓝色拉丝、复古鬼影、强星芒、彩虹光环。点选预设会开启光晕并替换全部元素，一次撤销记录。
  - 自定义光晕保存在浏览器的 IndexedDB 中，最多 20 个，同名替换。
  - 光晕参数随工程文件和调色预设保存。预设中不保存光源和元素 id；套用调色预设时保留当前选择的光源。
- **命名**：Bloom 在界面中改称“泛光”，避免与镜头光晕混淆。
- **已知问题**：
  - 可见度只考虑立绘和天空，不考虑遮挡层中挡在立绘前面的物体。
  - 光晕叠加在明亮的天空上时不明显，这与真实镜头一致；需要更明显时可以提高整体强度。
- **验收结论**（2026-10-20）：通过，没有需要修改的地方。

#### M8.3 立绘变形

- **两种工具**（立绘步骤新增“变形”分组）：
  - **四角透视**：拖动四个角，按单应变换整体变形，用于贴合地面、墙面的透视。
  - **网格变形**：控制点网格默认 4×4，可调为 3×3 到 6×6。控制点之间按平滑样条插值，用于轻微弯曲、贴合表面、调整比例。
  - 两者可以叠加：四角透视按单应变换整个网格，之后仍可拖动单个控制点。
- **坐标**：变形在立绘自身的坐标中进行，位于移动、缩放、旋转、翻转之前，所以移动立绘后变形保持不变。控制点按立绘尺寸归一化保存，可撤销，保存在工程文件中。
- **管线**：
  - 先用 GPU 把立绘画到一张细分网格上，得到“变形后的立绘”。它替代原立绘，进入现有的全部流程：颜色统计、法线、自动接地点、阴影、遮挡、景深、导出。
  - 立绘的深度图按同一网格变形，不重新推理。
  - 手动接地点记录在原立绘坐标中，经变形换算到新位置。
  - 拖动控制点时只实时更新变形后的立绘；法线和颜色统计在松手后重新计算，与移动立绘的方式一致。
  - 导出时按立绘原分辨率变形，受纹理上限约束。
- **限制**：二维画作被变形后，线条会被拉粗或压细，也不能改变姿势和视角。这个功能定位为透视贴合和轻微调整，界面上提供重置。操控变形（在关节处钉图钉弯曲肢体）暂不做。

M8.3 实现说明（与上文不同的地方）：

- **变形模型**：W(p) = H(G(p))，坐标都是立绘 UV（src/fusion/warp.ts）。
  - G 是 n×n 个控制点的 Catmull-Rom 双三次样条，经过各控制点。边界外按相邻两点线性延伸一圈，所以默认网格严格恒等。
  - H 是把单位正方形映射到四角的单应变换。
  - 控制点和四角按立绘尺寸归一化，范围 [−1, 2]，随撤销和工程文件保存。文件中的变形不可用时按不变形处理。
  - 换成同样尺寸的立绘时保留变形，否则重置。
- **拖动**：
  - 四角透视的控制点在变形后立绘的四个角上。拖动时网格变形不变，重新求把网格四角映射到新四角的透视。
  - 网格变形的控制点显示在透视之后的位置，拖动时经透视的逆变换换算回网格坐标。
  - 四角不构成凸四边形、越过地平线、超出范围时，不接受这次拖动，控制点停在上一个可用的位置。
  - 双击控制点复位：透视的角去掉这个角的透视，网格的点回到默认位置。改变网格密度时，新控制点按现有形状取值。
  - 画布工具（摆放 / 四角透视 / 网格变形）是界面状态，不参与撤销。选择变形工具时摆放控件隐藏，接地点只显示、不能拖动。摆放控件的外框跟随变形后的立绘。
- **渲染**（src/engine/warp.ts）：
  - 变形的对象有六张纹理：立绘、立绘深度的引导滤波系数和辅助数据、深度法线、融合法线、轮廓光边缘带。它们按 64×64 的细分网格画到变形后的包围盒里。
  - 各 pass 按包围盒采样：新增 charOffset，charSize 改为包围盒的尺寸。没有变形时直接使用原纹理。
  - 包围盒的左上角对齐原立绘的像素。纹理尺寸取 32 的倍数，包围盒随之向右下扩展。这样不变形的区域逐像素复制，不会因重采样变模糊。
  - 按原立绘的分辨率变形，并受两个上限约束：纹理面积不超过原立绘的 2 倍（至少 2048²），尺寸不超过纹理上限。导出使用同一套纹理，即按原分辨率变形。
  - 轮廓光边缘带中的距离以原边缘带图的长边为单位，渲染时换算到变形后纹理的像素。
- **几何统计**（与计划不同）：
  - 融合 Worker 把原立绘的 alpha 按同一网格光栅化，重新统计不透明区域：包围盒，以及每一行的左右范围。颜色统计的取样范围、自动接地点和站立阴影都用这个结果。
  - 拖动时请求合并：上一次算完才开始下一次，结果到达前沿用上一次的结果。
  - “立绘底部被图片边缘截断”（半身像）仍按原立绘判断。
  - 手动接地点和焦点记录在原立绘坐标中，经变形换算到画面上。在画布上拖动它们时，经逆变形换算回原立绘坐标；拖到立绘之外时，取外框上最近的点。
- **法线**（与计划不同）：融合法线和轮廓光边缘带随立绘一起实时变形，不在松手后重新计算。重新计算需要变形后的立绘像素和深度，拖动时会与画面错位。代价是法线的方向不随透视旋转，透视很强时明暗略有偏差。
- **已知问题**：
  - 变形会拉粗或压细线条。
  - 网格控制点拖得很远时网格会折叠，画面重叠。这种情况不拦截，由用户避免。
  - 立绘的深度浮雕只是跟着变形重采样，前后关系不随透视改变。
  - 变形后的立绘纹理与原立绘纹理同时存在，大立绘的显存占用约增加一倍。
- **验收结论**（2026-10-20）：通过，没有需要修改的地方。

#### M8.4 水面倒影

- **适用范围**：使用水体遮挡方式的地方，包括区域外的默认方式和水体区域。倒影只出现在水体所在的范围内、水线以下。
  - 水线就是现有的过接地点的水平线。
  - 人物站在水边或积水地面上时，把接地点放在脚底、在积水处画出水体区域，也能得到倒影。
- **做法**：
  - 把立绘层（融合与立绘层调整之后）沿水线上下镜像，按现有的水面波纹偏移采样。
  - 离水线越远，按 mip 取得越模糊。
  - 反射率按菲涅尔近似：视线越贴近水面，倒影越清晰。
  - 倒影叠加水的颜色后，盖在背景的水面上。
  - 立绘本身和其他遮挡物仍在倒影之上。
  - 倒影参与景深，按立绘的深度模糊。
- **参数**：倒影强度（默认 0）、模糊、波纹扰动、水色。
- **限制**：只为立绘生成倒影（照片中原有物体的倒影已经在照片里）。倒影是正面的镜像，严格来说真实倒影会看到人物底面的一部分，一般看不出差别。

M8.4 实现说明（与上文不同的地方）：

- **参数**：每种遮挡方式各有一组倒影参数（区域外和每个区域分别设置），与水线高光、波纹一样只在水体方式下起作用。
  - 倒影强度默认 0。旧工程没有这些字段，读入时取默认值，画面不变。
  - 倒影模糊、倒影波纹默认 30%。水色为 sRGB 颜色，默认白色，即不改变倒影的颜色。
  - 面板上先只显示倒影强度，大于 0 时才显示其余三项。
- **镜像**（与计划不同，不在合成时按镜像坐标采样立绘层）：
  - 倒影开启时，把立绘层和立绘层调整按水线上下翻转的映射再渲染一次，得到与当前渲染目标逐像素对齐的“镜像立绘”。翻转只改输出 UV 的纵向偏移和缩放。
  - 这样分块导出时每一块各自得到自己的镜像，立绘超出画面的部分也能出现在倒影里。
  - 立绘层调整的局部调整系数是整幅图像的，按翻转后的 UV 取到立绘原处的系数；tone 按镜像重新计算。
  - 代价是开启倒影时立绘的融合和调整多算一次。倒影强度为 0 时不分配镜像图层，也不做额外渲染。
- **合成**（src/engine/passes.ts）：倒影在遮挡之后、遮罩着色之前叠加。
  - 只出现在水体方式的范围内、波动的水线以下，水下的立绘也被倒影覆盖。
  - 采样位置加上波纹扭曲：横向为主，沿纵向变化快，幅度为立绘高度的 3% × 倒影波纹。
  - 模糊用 mip：半径为离水线的距离 × 0.15 × 倒影模糊，再与立绘深度处的弥散圆合成。这样倒影跟随立绘离焦，但不单独经过景深的采样。
  - 反射率用 Schlick 近似，相机水平、地平线在画面中央（与站立阴影的假设一致）。视线越贴近水面越接近 1，垂直向下时为 0.3。真实水面垂直时只有约 2%，这里留得较高，让倒影强度在画面下方仍然起作用。
  - 结果为 背景 × (1 − R·α) + 镜像立绘 × 水色 × R，其中 R = 倒影强度 × 反射率 × 水线以下的遮罩。多个水体区域重叠处，参数按权重平均。
- **分块导出**：倒影在画面底部的 mip 模糊半径与弥散圆一样参与块的对齐和扩展量，波纹扭曲计入扩展量。分块与整幅渲染逐像素一致（相差不超过 1）。
- **已知问题**：
  - 倒影是镜像，不是从水面以下看到的人物底面，坐在水边、俯身的姿势与真实倒影有差别。
  - 相机不水平（俯拍、仰拍）时反射率的分布有偏差，可以用倒影强度弥补。
  - 从原图裁剪背景的分块导出中，立绘原处可能不在这一块裁剪的背景范围内，倒影里的 Light Wrap 取到裁剪边缘的背景，与整幅渲染略有不同。
- **验收结论**（2026-10-20）：通过，没有需要修改的地方。

#### M8.5 相机标定与透视

2026-10-20 与维护者确定：在 3D 光源编辑器之前先标定相机。

- **起因**：到 M8.4 为止，相机只有一个手动的视场角，其余都是假设：主点在画面中心、相机水平、地平线在画面正中。
  - 这些假设分散在光源方向、站立阴影的地面法线、水线、倒影的翻转和反射率中。
  - 俯拍、仰拍或画面倾斜的照片中，倒影、水线和站立阴影因此不符合直觉。
- **范围**：本阶段只做手动标定，不做自动估计。
  - 导入背景后要求用户先标定相机。
  - 旧工程暂不考虑兼容：打开时相机按未确认处理，倒影和阴影可能与之前不同。

**(1) 相机模型**

工程中新增 camera：

- **视场角**：长边方向，从光源步骤移到这里。光源分析、灯的位置等都使用它。
- **俯仰与倾斜**：俯仰是光轴相对水平面的角度，向上为正；倾斜是地平线在画面中的旋转角。
  - 两者决定画面中的地平线和世界的上方向：地平线到画面中心的垂直距离等于 焦距 × tan(俯仰)。
- **朝向**：只决定地面网格的方向。平行线标定时由第一组线决定。
- **相机高度**：参考值，默认 1.6 m。只用来换算地面网格的间距和人物的身高读数，不影响画面。
- **主点**：固定在画面中心。
- **已确认**：是否已经确认过标定。

**(2) 标定流程**

- **新增“相机”步骤**：位于素材和深度之间。
  - 导入背景、进入编辑器后直接打开这一步。
  - 确认之前，除素材外的其他步骤都不能进入，面板顶部说明原因。
- **初始结果**：相机水平、地平线在画面正中、视场角 60°（即之前的假设），叠加地面网格。
  - 不做自动估计，这个初始结果就是先显示给用户的估计值。
  - 用户调整到与照片相符后，按“确认相机”。
  - 照片中的地平线确实在正中、相机水平时，可以直接确认。
- **之后的修改**：
  - 确认之后仍可随时回到这一步修改，修改可以撤销。
  - “确认”本身不进入撤销记录，撤销不会回到未确认的状态。
- **更换背景**：标定作废，需要重新确认。撤销更换背景时，恢复原来的标定。

**(3) 两种标定方式**

- **地平线**（默认，适用于任何照片）：
  - 在画布上拖动地平线：两端的控制点改变高度和倾斜，拖动线本身上下平移。另外调视场角。
  - 也可以在面板中直接输入俯仰和倾斜。
  - 大角度俯拍、仰拍时，地平线可以拖到画面之外。
  - 看不到地平线时，按地面网格是否平铺在地面上来判断。
- **平行线**（参考 fSpy，适用于建筑、街道、室内）：
  - 沿照片中两组互相垂直的平行边各拖两条线。第二组可以选择是水平方向还是竖直方向。
  - 由两个消失点求出焦距和相机的旋转，方法见 Guillou 等人 2000 年的论文 Using Vanishing Points for Camera Calibration and Coarse 3D Reconstruction from a Single Image。按论文自行实现，不复制 fSpy 的代码（GPL-3.0）。
  - 拖动时实时求解。不能求解时显示原因，保持上一个可用的结果。不能求解的情况包括：一组线在画面上平行（消失点在无穷远）、两组方向不可能互相垂直。
  - 求解后切换回地平线方式，可以继续微调。
- **地面网格**：
  - 在相机步骤中始终显示，在立绘步骤中可以打开，作为摆放立绘的参考。
  - 网格铺在地面上，间距 1 m（按相机高度换算），向地平线方向逐渐淡出。

**(4) 接入现有流程**

相机水平、地平线在画面正中时，水线、倒影和站立阴影与之前的结果一致。

- **立绘摆放**：
  - 拖动立绘时按透视自动缩放：人物在场景中的身高保持不变，接地点跟着拖动走，离得越远越小。
    - 可以关闭。
    - 接地点在地平线以上（不在地面上）时不缩放。
  - 显示人物的身高读数（按相机高度换算），帮助判断大小是否合理。
  - “按相机透视”：按相机的俯仰给立绘加上竖直方向的透视，俯拍时上宽下窄。
    - 结果写入 M8.3 的四角透视，人物在画面中的高度不变。
    - 之后可以继续调整或重置。
- **水线**：
  - 水面是过接地点的水平面。
  - 水线是画面中过接地点、与地平线平行的直线，画面倾斜时水线也倾斜。
  - 水下的覆盖、折射、水线高光和倒影的模糊都按到这条线的距离计算。
- **倒影**：
  - 把立绘看作立在接地点上的竖直平面，倒影是它关于水面的镜像在画面上的投影。
    - 竖直平面的横向取相机横轴在地面上的投影，相机水平时与画面平行。
    - 平面到平面的投影是单应变换，用它替换 M8.4 的上下翻转。镜像渲染的框架不变，输出 UV 的映射增加一个透视矩阵。
  - 俯拍时倒影比人物短，画面倾斜时倒影随之倾斜。
  - 反射率按视线与水面的真实夹角计算。
- **站立阴影**：地面法线改为标定出的上方向，俯拍、仰拍时阴影的方向和长度随之正确。
- **光源**：
  - 光源方向仍然按相机空间保存。
  - 方向球上的方位和仰角仍然相对相机；改为相对地面放到 M8.6 的 3D 视图中处理。

**(5) 限制**

- 主点固定在画面中心，裁剪过的照片标定会有误差。
- 不校正镜头畸变。
- 不做 fSpy 的单消失点方式（一组线加已知焦距），可以用地平线方式代替。

M8.5 实现说明（与上文不同的地方）：

- **相机模型**（src/camera/）：
  - 相机空间 x 向右、y 向上、z 指向观察者。上方向 = (−sin 倾斜·cos 俯仰, cos 倾斜·cos 俯仰, −sin 俯仰)，地面是 上方向·X = −相机高度 的平面。
  - 范围：视场角 15–120°，俯仰 ±80°，倾斜 ±45°，相机高度 0.1–100 m。
  - 视场角从光源步骤移到相机步骤，光源分析、方向球、光芒、镜头光晕、景深等原来读光源视场角的地方都改读相机的视场角。
- **步骤与确认**：
  - 未确认时，导航栏上需要相机的步骤变暗，点击时弹出提示并停在相机步骤；工具栏的导出按钮同样处理。
  - 光源自动分析在确认相机之后才开始，因为它要用视场角换算方向。深度估计不受影响。
  - 确认对撤销历史中同一背景的所有记录生效，撤销、重做不会回到未确认。
  - 更换背景后直接跳到相机步骤。旧工程没有 camera 字段，读入时取初始值、未确认，打开后停在相机步骤。
- **地平线方式**：
  - 地平线两端的控制点在画面宽度的 15% 和 85% 处，只能上下拖动。地平线超出画面较远时，可以缩小视图或直接调滑块。
  - 面板中有视场角、俯仰、倾斜三个滑块，另有“网格朝向”（±45°），只转动地面网格，便于和照片中的地砖、路面对齐，不影响画面。
- **平行线方式**：
  - 切换到平行线方式时，按当前的标定生成两组“井”字形的线段，求解结果与当前一致；放不进画面时缩小一些。
  - 切换第二组的方向会按当前的标定重新生成线段，“重新放置线段”同理。
  - 不能求解的原因有四种：第一组平行、第二组平行、两组不可能垂直、结果超出范围。相机水平时第二组选竖直方向会因为竖直线平行而不能求解，提示改用地平线方式。
  - 拖动线段端点是一次撤销。线段端点可以拖到画面之外（不超过画面尺寸的一倍）。
- **立绘摆放**（立绘面板“相机透视”一节）：
  - 透视缩放只在拖动立绘移动时起作用；接地点、身高都按立绘不透明部分的包围盒计算，与站立阴影一致。
  - 身高读数按头顶到接地点的画面高度换算，接地点不在地面上时显示原因。
  - “按相机透视”以去掉已有四角透视后的立绘为准，所以重复使用结果基本不变（包围盒随变形更新，读数可能差约 1%）。画面倾斜时立绘也随之倾斜，与照片中竖直的边一致。
  - 立绘步骤的地面网格以接地点为中心，叠加虚线的地平线；接地点不在地面上时放在默认位置。
- **水线、倒影**（src/focus/params.ts、src/engine/）：
  - 水线以“过接地点的点 + 指向下方的法线”传入着色器，覆盖、折射、高光、倒影模糊都按到这条线的有符号距离计算。
  - 镜像渲染把 M8.4 的翻转换成文档 UV 中的单应矩阵；分块导出时每块的输出 UV 先映射回整幅画面再乘这个矩阵。
  - 反射率的入射角取视线与标定的上方向的夹角。
  - 分块导出的扩展量按画面四角到水线的最大距离估计。
- **站立阴影**：地面法线取标定的上方向；接触阴影的椭圆沿地平线方向旋转。
- **验证**：相机水平、地平线在画面正中时，站立阴影和倒影的导出与改动前逐像素一致（WebGPU）。
- **已知问题**：
  - 网格朝向保存在工程中，但目前只用于显示网格；M8.6 的 3D 视图可能用它确定场景的朝向，届时再决定。
  - 地平线方式没有吸附，拖动地平线时精度受缩放影响，精调用滑块。

**M8.5 补充：参考形状、尺寸标定与操作改进**

2026-10-20 维护者试用后确定：标定本身可用，但操作不便，缺少直观的预览。具体问题有三个：

- 不清楚地平线的作用。
- 相机高度是手填的估计值，用户会以为它和朝向一样是标定出来的。
- 只有一张固定的地面网格，没有 fSpy 那样可拖动的参考形状来验证标定。

(1) 视平线

- “地平线”改称“视平线（地平线）”，标定方式改称“视平线”和“平行线”。
- 面板第一行和画布上的标签说明它是什么：
  - 视平线是与镜头一样高的水平面在照片中的位置，即海天交界、平原尽头。
  - 室内看不到它，但与镜头一样高的东西都在这条线上。
  - 线在画面中心以上是俯拍，在中心以下是仰拍；线倾斜说明画面倾斜。
- 平行线方式下，每组线延长到消失点并标出。视平线穿过水平方向的消失点，可以看出它是由平行线求出来的。

(2) 参考形状与原点

- **种类**（单选，默认地面网格）：
  - 地面网格。
  - 沿红轴的竖直网格、沿蓝轴的竖直网格。
  - 立方体。
  - 无。
- **原点与坐标轴**：参考形状放在地面上的原点处，画出三根坐标轴：
  - 红轴（X）和蓝轴（Z）为水平方向，绿轴（Y）向上。
  - 平行线的颜色与轴对应：第一组为红色；第二组为水平方向时是蓝色，为竖直方向时是绿色。
- **拖动**：原点和所有参考形状都能拖动，在地面上平移，按下的那一点始终跟着光标。
  - 原点不能拖到视平线以上。
- **旋转**：
  - 视平线方式下，拖动红、蓝箭头可以绕竖直方向旋转，即原来的“网格朝向”。面板上的“参考方向”滑块范围改为 ±180°。
  - 平行线方式下，方向由第一组线决定，红轴沿第一组线。
- **尺寸**：与 fSpy 一样，网格和立方体的大小按原点到相机的距离换算，拖到画面哪里都差不多大。它们只用来检查透视，不代表实际尺寸；实际尺寸用测量杆检查。“大小”倍数可调（0.25–4×），同时作用于网格和立方体。
- **2026-10-21 调整**：维护者试用后确定。
  - 原来网格每格 1 m、立方体边长按米计，拖远变小、拖近变大，不便检查，改为上面的方式。
  - 删去人形标尺。
- **保存**：
  - 参考形状、原点位置、暗化都是界面状态，不进工程，也不进撤销记录。参考方向仍保存在工程中，可以撤销。
  - 更换背景后，原点回到默认位置。
- **立绘步骤**：
  - “显示地面网格”改为“显示参考形状”，种类和大小与相机步骤共用。
  - 原点固定在立绘的接地点，随立绘移动。

(3) 看清楚、拖得准

- **暗化图片**：相机步骤中默认开，可以关闭。
- **放大镜**：拖动视平线端点、平行线端点、原点、测量杆时，在光标附近显示放大 3 倍的照片和十字准星。
- **端点**：改为空心的准星，不挡住要对准的位置。

(4) 场景尺寸

- **为什么要标定**：面板中说明。
  - 单张照片只能求出相机的方向和视场角，求不出大小：同样的画面，可能是真实的街道，也可能是缩小的模型。
  - 需要告诉程序画面中某个东西有多高，才能确定相机离地面多高。
  - 它决定测量杆的读数和立绘的身高读数（参考形状按 2026-10-21 的调整不再随它变化）。不标定时，人物可能被摆得像巨人或小人而不自知。之后的 3D 视图也按它确定距离。
- **测量杆**（只做竖直方向，维护者确定；沿地面方向的已知长度暂不做）：
  - 底端在地面上，拖动底端或杆身时整根杆在地面上移动，高度不变。顶端只能沿竖直方向拖动。旁边显示杆的高度。
  - 把杆对准照片中已知高度的物体（门约 2.0 m、成年人 1.6–1.8 m、轿车约 1.5 m、一层楼约 3 m），填入实际高度，按“按测量杆设定”，相机高度按比例换算。
  - 设定之后，把杆拖到别的物体上可以读出它们的高度，用来检查。
- **直接填写**：也可以直接填写相机高度，例如三脚架的高度。
- **来源**：记录尺寸的来源（默认值、手动填写、测量杆），在面板和确认区显示。尚未标定时提示，但不阻止确认。

(5) 结果栏

两种方式统一显示：横向和纵向的视场角、俯仰、倾斜、参考方向、相机高度及其来源。

(6) 不做的部分

- 立绘身高输入：维护者确定不做。现在已经能估计身高，由用户自己调整。
- fSpy 的单消失点模式、手动主点 / 第三消失点、矩形模式、导出到 Blender：对溶图帮助不大，会让操作更复杂。

(7) 提交顺序

参考形状与原点 → 放大镜与暗化 → 测量杆与结果栏 → 视平线说明与消失点 → 立绘步骤。

M8.5 补充实现说明（与上文不同的地方）：

- **参考形状**（src/camera/guides.ts、src/canvas/CameraGuide.tsx）：
  - **尺寸**：
    - 单位长度 = 原点的深度 × 0.1 × 画面长边 / 焦距，即在原点处约为画面长边的 1/10。这样相机高度改变时，参考形状在画面上也不变。
    - 地面网格以原点为中心，向四周各 60 格。
    - 竖直网格宽 10 格、高 4 格。
    - 立方体以原点为底面中心，边长 2 个单位。
    - 坐标轴长 1 个单位，不随“大小”倍数变化。
  - **裁剪**：所有形状只画在画面范围内。相机后方的部分在离相机 0.05 × 相机高度处截断。
  - **拖动**：
    - 按下的点取光标视线与形状所在平面的交点：地面网格取地面，竖直网格取所在的竖直面，立方体取过原点、正对相机的竖直面。
    - 单位长度随原点的深度变化，所以拖动时按下的点是 原点 + 单位长度 × 固定偏移。令它落在光标的视线上、原点在地面上，解一个线性方程（Sherman–Morrison）。
    - 求不出或原点会到相机后方时不移动。
  - **旋转**：按住 Shift 以 15° 为步进。平行线方式下不显示旋转把手。
  - **原点**：
    - 默认在画面下部中央；那里不在地面上时，取视平线以下的一点。
    - 面板中可以“放回默认位置”。
    - 标定改变后，原点仍在地面上就保持不动。
- **平行线与参考方向**：
  - 平行线方式求出的参考方向规范到 (−90°, 90°]，红轴指向画面右侧。
  - 切换到平行线方式时，第一组线沿红轴、第二组沿蓝轴生成。某个方向在画面中太接近视线方向（小于 15°）时，改用 ±45° 的两个方向。
- **放大镜与暗化**（src/canvas/Loupe.tsx）：
  - 放大镜直径 150 px，放大倍数是当前视图的 3 倍。默认在控制点左上方，靠近窗口边缘时翻到另一侧。
  - 拖动视平线本身时，放大镜跟着光标所在的那一点。
  - 暗化是在画面上叠加 45% 的黑色。
- **测量杆**：
  - 默认底端在画面宽 30%、高 85% 处，高 1.7 m。那里不在地面上时，放在原点左侧。
  - 位置是界面状态，不进撤销记录。最小高度 0.05 m。
  - 测量杆画在视平线之上：它的顶端常在视平线附近，小的控制点优先拾取。
  - “按测量杆设定”：相机高度 × 实际高度 / 测量值，记一次撤销。设定后测量杆读数等于填入的实际高度。
- **场景尺寸的来源**：
  - 来源保存在工程中，旧工程读入时为“默认值”。
  - 拖动相机高度滑块记为“手动填写”，按测量杆设定记为“测量杆”。
  - 尚未标定时，确认区和已确认区都显示提示。
- **结果栏**：两种方式都显示。横向、纵向视场角按焦距换算。
- **视平线**：
  - 标签“视平线（与镜头等高）”写在右侧控制点的左边、天空一侧，因为左侧默认放着测量杆。立绘步骤的虚线视平线也带这个标签。
  - 面板中对视平线的解释放在“标定方式”一节的开头。
- **消失点**：
  - 平行线方式下，每组线的虚线延长线至少画到消失点，消失点用该组的颜色标出。
  - 消失点离画面中心超过长边的 20 倍时，当作几乎平行，不标出。
- **立绘步骤**：
  - “显示参考形状”打开时，可以选择种类（不含“不显示”），与相机步骤共用。在相机步骤中选了“不显示”时，打开开关会改回地面网格。
  - “大小”倍数也与相机步骤共用。
  - 立绘步骤中的参考形状不能拖动，原点随立绘的接地点移动。
- **已知问题**：
  - 参考方向仍然只用于参考形状，M8.6 再决定是否用于确定 3D 场景的朝向。
- **验收结论**（2026-10-21）：通过。
  - 第一次交付后，维护者认为标定可用，但操作不便、缺少直观的预览，于是按上面的补充改进。
  - 补充交付后，维护者要求参考形状在画面上大小不变，并删去人形标尺。
  - 改完之后没有其他需要修改的地方。
- **验收后补充**（2026-10-21，维护者提出）：相机步骤的画布只显示背景原图，不画立绘，也不做重光照、景深、遮挡、调色、后期等任何处理，标定时看到的就是照片本身。

#### M8.6 3D 光源编辑器

2026-10-21 与维护者确定：
- **拆分**：M8.6 工作量大，分两次验收。M8.6a 做 3D 视图与光源，M8.6b 做立绘深度编辑。
- **深度校准**：校准后的深度用于 3D 视图，也用于点光源的重光照。3D 中看到的灯与人物的距离，就是重光照计算用的距离。
- **光源方向**：方向球、方位、仰角改为相对地面。

**M8.6a 3D 视图与光源**

(1) 深度校准

- **问题**：深度模型输出的是 [0,1] 的相对逆深度 d（1 为最近），只确定到一个尺度和偏移。现在的光源分析和重光照用“伪深度” 1/(d + 平移量)，远近比例是任意的。
- **做法**：
  - 设真实深度 z（米，沿光轴）满足 1/z = a·d + b。
  - 视平线以下、非天空的像素，按 M8.5 标定的地面可以算出“如果这里是地面”的深度 z_g。
  - 用这些像素的 (d, 1/z_g) 稳健地拟合 a、b，例如先 RANSAC，再在内点上用最小二乘细化。
  - 站在地面上的物体比地面近，自然成为离群点。
  - 单位来自相机高度：测量杆标定过时是真实尺寸，没标定时按默认的 1.6 m。
- **结果**：
  - 拟合成功的条件：内点足够多、覆盖的深度范围足够、a > 0。
  - 失败时（地面不可见、内点太少）退回伪深度。伪深度按比例换算，使接地点处与地面的距离一致。
  - 面板中显示校准状态：已按地面校准，或使用近似深度及原因。
  - 比照片中最远的点还远、或 1/z ≤ 0 的部分当作远处，限制在一个最大距离内。
- **使用范围**：
  - 3D 视图中的背景、立绘、灯。
  - 点光源的重光照，包括立绘中心的位置和二维的灰球预览。启用灯时的光照结果会与之前不同。
  - 太阳 / 天光、景深、遮挡不变，它们只用到方向或相对远近。
  - M8.7 的投影也使用它。
- **更新时机**：背景深度或相机标定变化时重新拟合。拟合在主线程或 Worker 中进行，采样约几千个像素，耗时可以忽略。

(2) 光源方向相对地面

- **含义**：
  - 仰角是光源方向与地面的夹角，即太阳高度角。
  - 方位在地面内量，0° 为从相机一侧照向场景（顺光），正值来自右侧，±180° 为逆光。
  - 0° 的方向是相机视线在地面上的投影。参考方向只用于参考形状和 3D 视图的地面网格，不影响方位。
- **范围**：方向球、方位和仰角滑块、光源分析报告中的方位和仰角，都改为这个参照。
- **数据**：工程中仍按相机空间保存方向，光照结果不变，旧工程不受影响。
  - 重新标定相机后，同一方向的方位、仰角读数会随之变化。因为光源是从照片中估计出来的，相对相机的方向才是确定的。

(3) 3D 视图

- **入口**：光源步骤中切换“3D 视图”，画布变为三维场景，再切换回二维。光源面板保持不变，选中、改色、改强度等操作在两种视图中通用。
- **坐标**：
  - 场景按标定的相机摆正，地面是 y = 0 的水平面，原相机在地面以上相机高度处。
  - 地面上画一张淡的网格，朝向与参考方向一致，每格 1 m（按场景尺寸）。
- **背景**：
  - 用校准后的深度把背景展开成一张贴着照片的网格，约每 4 个深度像素一个顶点，贴背景原图。
  - 相邻顶点的深度相差过大（深度跳变）的三角形被剔除，避免前后物体之间被拉成薄膜。
  - 天空放在远处的穹顶上。
- **立绘**：
  - 立在接地点处，所在深度与重光照一致：用户设置的前后位置，或接地点附近的背景深度。
  - 从原相机看过去时，立绘与二维画面完全重合。
  - 正面按立绘的深度图和厚度起伏，贴融合后的立绘，即重光照、颜色匹配之后的结果。
- **光源**：
  - **太阳 / 天光**：画在以立绘为中心的大球面上，带指向场景的箭头。在球面上拖动改变方向，按住 Shift 以 15° 为步进。
  - **灯**：画成灯泡，外面有一个淡的球，表示光强减半的范围。
    - 拖动灯泡时，在与视线垂直的平面内移动。按住 Alt 拖动时，沿视线方向前后移动。
    - 按住 Ctrl 点击背景或立绘时，灯放到所点的表面附近，稍微离开表面。
    - 灯可以悬在空中。
    - 灯不能放到原相机后方，因为工程仍按“画面坐标 + 深度”保存灯的位置；深度的范围放宽，可以比照片中最近的物体还近。
    - 二维中拖动灯时，仍然吸附到光标处表面的深度，与之前一致；需要悬空时在 3D 中摆放。
  - 未启用的光源画成半透明。选中的光源高亮，与面板同步。
- **预览**：
  - 立绘旁边放一个灰球，按现有的重光照模型着色，能直接看出哪一侧被照亮。
  - 右下角显示二维合成的小预览，3D 中的修改实时反映在小预览上。
- **视角**：
  - 默认围绕立绘环绕旋转，可以缩放和平移。
  - “回到相机视角”：三维视角与原相机重合，场景与二维画面重叠。
  - 不在相机视角时，画出原相机的位置和视锥。
- **同步**：3D 视图中的修改与二维面板是同一份数据，共用撤销记录，一次拖动记一次撤销。
- **渲染**：
  - 3D 视图与二维共用同一个渲染器。
  - 二维合成渲染到离屏目标，用作立绘浮雕的贴图和小预览。
  - 目标不低于 30 fps。
- **说明**：界面上注明 3D 场景是由单张照片的深度重建的“2.5D 浮雕”，看不到物体背后，比例是近似的。

(4) 提交顺序

深度校准与点光源 → 光源方向相对地面 → 3D 视图与背景场景 → 立绘浮雕、灰球与小预览 → 3D 中摆放太阳和灯 → 测试与文档。

M8.6a 实现说明（与上文不同的地方）：

- **深度校准**（src/camera/depthScale.ts）：
  - 在引导分辨率上均匀取约 4000 个像素。天空遮罩超过 0.5 的不用；地面距离超过 60 倍相机高度的也不用，深度模型在那么远处已经分辨不出远近。
  - RANSAC 256 次，内点是预测的 1/z 与 1/z_g 相对误差不超过 15% 的点；再在内点上做两轮相对误差意义下的加权最小二乘。
  - 拟合成功需要：地面一侧至少 30 个采样；内点至少 30 个、占地面一侧的 15%；内点的 d 从 10% 到 90% 分位至少跨过 0.05；a > 0。
  - 最远距离取照片中 2% 分位的最远景物，且不超过 300 倍相机高度。
  - 近似的换算与伪深度同形：a = k、b = k × 0.1（伪深度的平移量）。k 取地面样本中 w/(d + 0.1) 的中位数；看不到地面时让最近处（d = 1）在相机高度的距离上。
  - 状态共五种：已按地面校准、没有深度、看不到地面、符合的点太少、深度范围太窄。深度面板显示校准状态和样本数。
  - 结果按深度结果和相机缓存。点光源的位置、立绘中心、二维灰球、站立阴影中点光源的方向都按校准后的距离计算；站立阴影判断某处是不是地面时，背景深度也按同样的换算转为距离。
- **光源方向**：方位、仰角滑块和方向球按地面坐标换算；“背光”开关把地面坐标中的前后分量取反。
- **3D 视图**（src/scene3d/、src/engine/scene3d.ts、src/canvas/View3D*.tsx）：
  - 背景网格长边约 320 个顶点。三个顶点到原相机的距离之比超过 1.25 时，这个三角形剔除。
  - 穹顶以原相机为中心，半径为最远距离的 1.5 倍。天空方向贴原图，其他方向是暗色。
  - 地面网格向视点拉近 5%，避免与照片中的地面互相穿插；格子在画面上太密时淡出。
  - **立绘浮雕**：
    - 在立绘包围盒（外扩 10%）内建网格，长边 192 个顶点。
    - 顶点着色器读引擎中的立绘深度图层，与景深、遮挡用的是同一个起伏。起伏按伪深度换算，再以立绘平面为基准缩放到校准后的距离。
    - 贴“立绘层调整”之后的结果，半透明的边缘用 alpha to coverage。
  - **视角**：
    - 环绕中心是立绘中心，没有立绘时是画面中心的景物。
    - 初始视角从原相机向右转 35°、向上转 20°，俯仰限制在 ±85°。
    - 滚轮缩放的范围是参考距离的 0.02–50 倍。
  - **渲染**：场景先渲染到 4 倍多重采样的目标，再画到画布上，并叠加二维结果的小预览。小预览在可见区域的右下角，宽不超过可见区域的 30%、高不超过 35%。
  - **灰球**：放在立绘右侧、与立绘中心等高，大小与二维灰球相同。着色也与二维灰球相同，即立绘中心处受到的光照，跟随“灰球预览”开关。
- **光源**：
  - **控件**：画在 SVG 层上，大小不随远近变化，也不会被场景挡住。
  - **太阳球面**：半径取参考距离的 0.6 倍和人物高度的 1.5 倍中较大的一个。
    - 从球面靠近视点的一侧开始拖动时，取视线与球面较近的交点，反之取较远的交点。
    - 视线不经过球面时，取球面上离视线最近的点，拖到球的轮廓之外也连续。
  - **灯**：
    - 拖动时显示落到地面的投影线和投影圈。
    - 按住 Alt 拖动时，沿视点到灯的方向按指数移动，向上拖动时远离视点，灯在屏幕上的位置不变。
    - 灯离原相机（沿光轴）至少 0.05 倍相机高度，太近或在后方时不移动。
  - **深度范围**：工程中灯的归一化逆深度上限放宽到 10⁴。面板的“前后位置”滑块仍是 0–100%，超过时滑块停在最右端，数值照常显示。
  - **光强减半的球**：半径是参考距离，即原相机到立绘中心的距离。视点靠近球面时淡出，进入球内时不画，否则整个画面会被掠射角的轮廓增亮蒙上一层灰。
  - **点选表面**：
    - 沿视线每步前进当前距离的 1%，在原相机的深度中找第一处从表面前方穿到后方的位置，再二分细化。
    - 穿到表面后方超过 25% 时，视为从深度跳变的空缺中穿过，继续向前。
    - 照片之外按标定的地面计算，因此点在画面外的地面网格上也可以。
    - 灯放在所点处沿视线后退参考距离的 4%，不超过到视点距离的一半。
  - **面板工具**：“在画面上添加”在 3D 中点到表面时添加灯，点到天空时添加太阳 / 天光，方向是所点的方向。吸管从背景原图取色。
- **验证**：
  - 合成场景（使用真实深度模型）按地面校准，2320 个地面采样中 1623 个符合。
  - 在 3D 中拖动太阳和灯时，帧间隔约 17 ms（WebGPU、WebGL2），与二维中拖动灯相同。
- **已知问题**：
  - 深度跳变处的剔除让前景物体的轮廓呈锯齿状。
  - 背景和立绘都只有正面，从侧面看较薄。
  - 3D 中的背景贴的是原图，不含阴影、景深等效果，最终效果看右下角的小预览。
  - 灯可以拖到地面以下。
- **验收结论**（2026-10-21）：通过，没有需要修改的地方。M8.5 的补充（相机标定步骤只显示背景原图）一同验收通过。

**M8.6b 立绘深度编辑**

- **入口**：3D 视图也可以在立绘步骤中打开。
- **沿地面移动**：在 3D 视图中把人物沿地面前后左右拖动。
  - 二维位置、接地点、前后位置随之更新。
  - 缩放按透视换算，人物在场景中的高度保持不变，与 M8.5 的“拖动时按透视缩放”一致。
- **厚度**：与景深步骤中的立绘厚度是同一个参数。在 3D 中调整时，浮雕即时变化，能看到哪些前景挡在人物前面。
- **深度修正画笔**：在立绘上推、拉，修正深度模型估计错误的地方，比如手臂被估计到身体后面。
  - 修正量作为一层低分辨率的增量保存在工程文件中，可撤销。
  - 修正后的深度用于法线、遮挡、景深和 M8.7 的投影。
  - 在 3D 中画时能直接看到浮雕的变化；二维立绘步骤中也可以画。

M8.6b 细化（2026-10-21 与维护者确定）：

- **画笔工具**：推（远离相机）、拉（靠近相机）、平滑（让修正处的起伏变平缓）、恢复（擦掉修正，回到模型估计的深度）。可以调大小、强度、硬度。
- **二维中的显示**：立绘步骤中选用深度画笔时，立绘上叠一层半透明的深度伪彩色，配色与深度步骤相同，只覆盖立绘。换用其他工具后恢复正常画面。

我的默认做法（未逐项询问）：

- **入口与工具**：
  - 立绘面板增加“立绘深度”一节：3D 视图开关（与光源步骤是同一个开关）、立绘厚度、深度画笔的开关与参数、“清除全部修正”。
  - 深度画笔与摆放、四角透视、网格变形一样是画布上的一种工具，同一时间只用一种。
- **数据**：
  - 笔画像遮挡区域的画笔一样记录：折线的点用变形前的立绘 UV，半径按立绘长边的比例。随工程保存，一笔一次撤销，换成另一张立绘时清空。
  - 笔画按顺序栅格化成一层低分辨率的增量（长边 256 像素），单位是立绘自身的归一化逆深度。画笔落点之间的间距是半径的 1/4。
  - 推、拉：一笔从中心划过，增量改变“强度 × 0.2”。平滑：向邻近的平均值靠拢，只在不透明区域内取平均。恢复：增量按比例衰减，强度为 100% 时划过一次基本恢复。硬度决定从中心到边缘保持全强度的范围。
  - 立绘深度还没有估计出来时不能用深度画笔。
- **修正后的深度用在哪里**：
  - 景深、遮挡、3D 浮雕、深度调试视图：着色器中立绘深度 = 引导滤波重建的深度 + 增量。增量随立绘一起变形。
  - 对焦点在立绘上时的深度、3D 中的点选：按同样的方式取值。
  - 立绘法线中的“深度法线”按修正后的深度重新计算。计算在融合 Worker 中进行，画完稍停后更新。
  - 起伏的基准（不透明区域深度的中位数）仍取原来的深度，修正一处不会让整个人物前后移动。
- **立绘步骤中的 3D 视图**：
  - 光源只显示，不能拖动；光源的添加和吸管工具不在这里使用。
  - 没有选用深度画笔时，在立绘上左键拖动即沿地面移动人物；在其他地方拖动仍是环绕。
  - 沿地面移动时，接地点跟随光标在地面平面上的位置，始终按透视缩放，与“拖动时按透视缩放”开关无关。前后位置为手动时，按新的接地点改成地面在那里的深度。
  - 选用深度画笔时，在立绘上左键拖动即画，光标处显示画笔大小的圆。

(5) M8.6b 提交顺序

细化文档 → 深度修正的数据与栅格化 → 修正后的深度用于渲染、法线和点选 → 二维深度画笔与伪彩色 → 立绘步骤中的 3D 视图：沿地面移动、厚度、在 3D 中画 → 测试与文档。

M8.6b 实现说明（与上文不同的地方）：

- **数据**（src/fusion/depthEdit.ts、src/state/depthEdit.ts）：
  - 每个落点的权重是“强度 × 落点间距比例 ÷ (1 + 硬度)”乘以衰减，一笔从中心划过时权重相加正好是强度。推、拉每次改变“权重 × 0.2”；平滑、恢复按 exp(−3 × 权重) 保留。
  - 平滑取平均的窗口半径是画笔半径的 1/3，只取不透明度不低于 0.5 的像素，用积分图计算。增量限制在 ±1。
  - 栅格化是增量进行的：正在画的一笔只处理新加的点；撤销、清除或立绘深度变化时从头重画。
  - 原深度和不透明度从引导分辨率的深度和长边 1024 的缩小图重采样到增量的分辨率。
  - 换成同样尺寸的立绘时保留笔画，与变形相同；尺寸不同时清空。工程文件中最多 2000 笔，每笔最多 10 万个点。
- **渲染**：
  - 增量以半精度纹理参与立绘变形，与其他立绘图层一起变形。
  - 深度法线在融合 Worker 中按修正后的深度重算，画完停 150 ms 后更新。
- **二维画笔**：
  - 深度画笔是立绘画布工具中的第四种，选用时“变形”一节的工具按钮都不选中。
  - 画笔大小是屏幕上的直径，4–300 px，默认 60 px。强度默认 50%，硬度默认 30%，可调到 95%。
  - 落笔时按落笔处的变形求局部比例，把屏幕上的半径换算成立绘长边的比例，限制在 0.1%–50%。屏幕上移动超过画笔直径的 1/8 才加点。
  - 伪彩色叠加的不透明度是 65%。
- **3D 视图**：
  - 立绘步骤中光标悬停时就点选表面，在人物上时显示移动光标或画笔圆。点选一次约 0.2 ms。
  - **沿地面移动**：
    - 按下时记下光标在地面（y = 0）上的位置和人物接地点在地面上的位置，拖动时接地点平移同样的距离，人物不会跳到光标处。
    - 接地点离原相机（沿光轴）至少 0.05 倍相机高度。
    - 前后位置为手动时，按标定地面在新接地点处的距离换算成归一化逆深度，限制在 0–100%。
  - **画笔半径**：屏幕上的半径按所点处到视点的距离换算成长度，再按到原相机的距离换算成文档像素，最后按变形换算到立绘上。
  - 3D 视图打开时，二维的摆放、变形、接地点和参考形状控件隐藏。立绘步骤的 3D 中不显示灰球。
- **验证**：
  - 合成场景中拉近一笔后，伪彩色沿笔画变亮，融合法线随之改变，WebGPU 与 WebGL2 的结果一致。
  - 立绘四角透视变形后，修正跟着变形后的立绘。
  - 3D 中向下拖动人物时，人物走近并按透视放大。
- **已知问题**：
  - 手动前后位置按标定的地面计算。相机标定不准时，会与照片深度在接地点处的值相差较大：合成场景中一处为 29% 对 62%。接地点在画面之外时，深度常停在 100%。
  - 在 3D 中拉近时浮雕随之变化，光标下的落点也跟着移动。

**限制**：深度模型只给出相对远近，也看不到物体背后。3D 场景是“2.5D 浮雕”：前后交界处会有空缺，比例在地面以外的地方也只是近似。它足够用来理解光源的前后左右，但不是真实的三维场景。

#### M8.7 屏幕空间投影与接触阴影

参考 Bend Studio 在《往日不再》（Days Gone）中使用的屏幕空间阴影。

- **遮挡体**：只有立绘（照片中原有物体的影子已经在照片里）。立绘在画面上每一处占据一段深度：正面取立绘深度图（含 M8.6 的修正），背面取正面加上立绘厚度。
- **做法**：
  - 背景的每个像素按深度重建出三维位置，朝主光源方向前进：方向光沿光线方向，灯朝向灯的位置。
  - 逐步投影回画面，检查这一点是否落在立绘占据的深度范围内，落在其中就算被遮挡。
  - 影子因此会贴着台阶、斜坡、墙面、长椅等表面弯折。
  - 近处用更小的步长，人物坐、靠在物体上时，接触处有细小的阴影。
- **立绘自身的投影**：对立绘像素做同样的检测，例如手臂挡在身前时的投影。结果乘在主光源的直射光上，与重光照一起计算。可以单独关闭。
- **柔和度**：按遮挡点到受影点的距离调整半影，离脚越远越模糊。阴影颜色沿用 M4 的估计方法。
- **与现有阴影的关系**：
  - 站立阴影的投影方式分为“平面”（现有方式）和“贴合表面”（新方式）。深度质量差时可以退回平面方式。
  - 接触阴影的椭圆保留。
  - 新方式的默认值在开发时确定，新工程是否默认使用新方式要等验收时确认。
- **分辨率**：阴影在不超过 2048 px 的代理分辨率上计算，再按深度引导上采样到输出分辨率。导出大图时与 Bloom 的做法相同，分块之间没有接缝。
- **限制**：深度只是相对远近，影子的长度和形状是近似的；只有照片里看得见的表面能接住影子。只计算主光源一个光源。

## 4. 用户流程

1. **素材**：拖拽、粘贴或选择背景和立绘。空状态只显示上传引导，不提供示例图。立绘没有透明区域时提示“请上传透明 PNG/WebP”。
2. **相机**（M8.5）：导入背景后先标定相机，拖动视平线或沿平行线标定，用可拖动的参考形状检查，用测量杆标定场景尺寸，确认后才能进入后面的步骤。
3. **深度**：首次使用时加载模型（显示进度，可切换模型源），然后自动推理；可查看深度、法线和天空遮罩。
4. **光源**：查看候选光源，用 Gizmo、方向球和灰球预览进行确认或修改；也可以在 3D 视图中查看和摆放光源、前后移动人物（M8）。
5. **立绘**：拖拽、缩放、旋转、翻转、调整前后位置，四角透视和网格变形（M8）；调节颜色匹配、重光照和边缘融合的强度，实时预览。
6. **景深**：对焦、光圈、深度遮挡。
7. **调色**：三级基础调整、色轮、LUT、混色。
8. **后期**：Bloom、Halation、光束（含轮廓光束）、镜头光晕（M8）、颗粒、暗角、色差。
9. **导出**：按背景原图的分辨率导出 PNG、JPEG 或 WebP（后两者可调质量）；也可以把参数和素材保存为 `.a2r` 工程文件，浏览器也会自动保存当前工程。

任何步骤都可以使用：前后对比滑块、撤销/重做、调试视图切换。

## 5. 渲染与性能

- **脏标记重算**：深度、法线、统计只在素材或立绘位置变化时更新；调节滑块只重跑下游 pass。
- **两档分辨率**：交互过程中降到 50% 分辨率，停止操作 200 ms 后渲染完整预览。
- **纹理预算**：一张 12.6 MP 的 RGBA16F 纹理约占 100 MB，因此预览上限为 2048 px。
- **导出**（M6）：输出背景原图的分辨率。导入时保留原始文件，原图超出纹理上限时预览使用缩小的位图，导出时从原图逐块裁剪。
  - 不超过约 830 万像素（2880²）且原图没有缩小时整幅渲染，与之前相同。否则分块渲染，每块向四周扩展一段边距一起渲染，只取中间的部分。
  - 边距覆盖各 pass 读取邻近像素的距离：景深的弥散圆（加上 mip 预模糊）、三级锐化、色差、水体折射，以及从原图裁剪背景时的 Light Wrap。块的左上角对齐到不小于弥散圆的 2 的幂（16–512），使景深的 16 像素统计块与整幅渲染一致。
  - 半径远大于边距的效果（局部调整的引导滤波系数、Bloom、Halation、光束）先在预览分辨率上整幅渲染一次，各块按输出图像的坐标采样这些结果。噪声匹配、颗粒和抖动按输出图像的像素坐标取值，接缝处连续。
  - PNG 由自带的编码器按条压缩（8 位 RGB，Paeth 滤波，`CompressionStream`），内存中只有压缩后的数据。JPEG、WebP 经由整幅画布编码，受浏览器画布（Chromium 为边长 32767、面积 2²⁸）和格式本身（WebP 边长 16383）的限制，超出时提示改用 PNG。
  - 自测：同一工程按 128 像素分块导出与整幅渲染相比，各通道最大差 1；去掉边距时接缝处相差 50 以上。输出大于预览（2600 × 1300）时，预览分辨率的系数和 Bloom 带来的差异最大 13，平均 0.1。
- **推理隔离**：推理在独立 Worker 中进行，模型只加载一次。
- **能力探测**：检测 WebGPU、`shader-f16` 支持情况、`maxTextureDimension2D` 等，结果显示在“关于”页面中。

## 6. UI 设计

### 6.1 布局

**PC 优先**：面向 1280 px 以上宽度，鼠标加键盘操作，支持快捷键。

- **画布**：全屏，背景用深色中性灰，避免干扰色彩判断。
- **左侧**：mdui `navigation-rail`，列出 8 个步骤。
- **右侧**：液态玻璃浮动检查器，内部使用 mdui 的 slider、switch、segmented-button，可折叠。
- **底部**：基于 Magic UI `Dock` 的液态玻璃工具栏，包含缩放、前后对比、撤销、调试视图、导出。
- **首屏**：主视觉是金色圆环流入地球的图标（按维护者提供的图标重建为 SVG：入场时线条依次画出，之后地球自转、高光沿圆环流入地球；系统要求减少动态效果时静止）；`BlurFade` + 衬线体标题（Instrument Serif，暖灰底色配香槟金强调色）；上传区加 `BorderBeam`；`ShimmerButton` 作为主按钮；模型加载时用 `AnimatedBeam` 展示“图像 → 深度 → 光源”的处理流程。

**移动端（次要目标）**：检查器改为底部抽屉，导航改为底部导航；预览上限降到 1024 px；支持双指缩放和旋转立绘；液态玻璃降级为毛玻璃。

### 6.2 设计语言整合

为避免三种风格混在一起显得割裂，按以下分工使用：

- **mdui**：负责所有交互控件，统一采用 Material 3 的行为和可访问性。
- **液态玻璃**：作为面板容器的材质，替代 M3 的 surface container。
- **Magic UI**：只用于动效和装饰，不承担表单交互。
- **主题色**：把 mdui 的 `--mdui-color-*` 变量映射为 Tailwind v4 的 `@theme` token，让同一套配色同时作用于三者。配色固定为暖灰底色配香槟金强调色，不随背景图变化（2026-10-19 决定取消动态主题）。

### 6.3 液态玻璃

- **范围**：导航栏、检查器、工具栏、取色器浮层、首屏的上传卡片和胶囊按钮、GPU 错误提示，以及 mdui 的对话框面板、菜单（含下拉框的菜单）、提示和消息条。
- **Chromium**：使用 SVG `feDisplacementMap` 配合 `backdrop-filter: url(#…)`。
  - **位移图**：在 canvas 上生成。先求超椭圆圆角矩形的 SDF，再按 Snell 定律计算折射偏移，数学参考 iyinchao/liquid-glass-studio（MIT）。
    - 圆角使用 CSS `corner-shape: squircle`（指数 4 的超椭圆），SDF 按表面实际的 `corner-shape` 与圆角半径生成，折射边缘与裁剪形状一致。胶囊形和提示保持 `round`。
    - 边缘是一圈凸起，宽度为短边的 30%，限制在 4–24 px。高度剖面为 h(s) = (1 − (1 − s)⁴)^¼，厚度为凸起宽度的 1.6 倍，折射率 1.5。
    - 视线从内侧取样，所以边缘处显示被压缩的内侧背景。R、G 通道编码 x、y 偏移，B 通道编码边缘高光：外沿约 1.5 px 的亮线加上凸起内侧的微光，按法线与左上方光源的夹角调制。
  - **滤镜链**：先用 CSS 的 `blur(6px) saturate(140%)` 处理背景（边缘按镜像延伸，不会发暗），再进入 SVG 滤镜：
    - 按位移图偏移；
    - 叠加着色（#1b1a18，55%）；
    - 叠加高光。着色放在滤镜里，高光才能盖在着色之上。
  - **不做色散**：原计划让 RGB 三通道使用不同偏移量形成色散，但这要多偏移两次再按通道合成。实测预览中拖动立绘时每帧多花约 4 ms（headless Chromium，步进间隔约 17 ms → 21 ms），而 1–2 px 的色边几乎看不出，因此取消。
  - **每个表面一个滤镜**：
    - 由 `ResizeObserver` 跟踪尺寸。尺寸连续变化时（如工具栏的放大动画）先拉伸现有的位移图，停止变化 120 ms 后再重新生成。
    - 位移图按尺寸缓存。
    - 滤镜放在表面所在的文档或 shadow root 中，因为 shadow DOM 里的 `url(#id)` 只在本 root 内查找。
  - **注意事项**：
    - 玻璃画在 `::before` 上，因为带 `backdrop-filter` 的元素会成为 fixed 子元素的包含块。
    - 玻璃元素自身不能设背景色，否则背景色会被当作玻璃后面的背景。悬停高亮用一层叠在玻璃之上、内容之下的元素实现。
    - 祖先元素带 `opacity < 1` 或 `filter` 时，玻璃只能看到这个祖先内部的内容。弹出层淡入的过程中会短暂只显示着色。
- **其他浏览器**：回退为 `backdrop-filter: blur(22px) saturate(140%)` 加 72% 着色，配内高光（上、左亮，下、右暗）和 135° 的菲涅尔渐变边框。
- **不透明**：在“关于”对话框中开启“减少特效”（保存在浏览器本地）或系统开启“降低透明度”（`prefers-reduced-transparency`）时，面板改为不透明，不做折射和模糊。
  - 玻璃本身没有动画。其他动效已遵循 `prefers-reduced-motion`。
- **输入框**：输入框和下拉框改为填充样式，底色半透明。描边样式的浮动标签需要不透明底色遮住描边，在玻璃上会显出一块黑底。
- **调试参数**：`?glass=liquid|frosted|solid` 可以强制指定模式。

| **M8.6a 3D 视图与光源** | 用标定的地面校准深度，点光源的重光照使用校准后的深度；光源方向相对地面；由深度重建的 2.5D 场景；在 3D 中摆放太阳和灯（§3.7） | 能在 3D 视图中看懂背景、人物和光源的空间关系；背景贴在地面网格上；拖动太阳和灯后二维画面同步更新；灯可以悬在空中；方位、仰角的读数符合直觉（仰角即太阳高度角）；回到相机视角时与二维画面一致；操作流畅（参考目标：不低于 30 fps） |
| **M8.6b 立绘深度编辑** | 立绘沿地面移动、厚度、深度修正画笔（§3.7） | 能在 3D 中前后左右移动人物，大小按透视变化；调整厚度和用画笔修正深度后，浮雕、法线、遮挡、景深随之变化；修正可以撤销并随工程保存 |
| **M8.7 屏幕空间投影** | 以立绘为遮挡体的屏幕空间投影与接触阴影；立绘自身的投影；平面与贴合表面两种投影方式（§3.7） | 影子落在台阶、墙面、长椅等不平的表面上并随表面弯折，方向与主光源一致；坐、靠时接触处有细小阴影；手臂等在身上投下影子；拖动立绘时阴影流畅更新；预览与导出一致 |

## 8. 验收流程

1. **交付**：每个阶段完成后，开发方提交一份验收说明，包括：
   - 本阶段完成的内容，以及与计划的差异
   - 启动或部署方式
   - 逐条可操作的验收清单
   - 开发期自测记录（单测结果、已测浏览器）
   - 已知问题
2. **验收**：维护者本人按验收清单执行，给出“通过”或“不通过”以及具体意见。开发方不自行宣布某个阶段已通过验收。
3. **推进**：阶段通过后才进入下一阶段。未通过的项目在当前阶段修复后重新提交验收。
4. **测试图像**：开发期的自动化测试只使用程序生成的合成图像（例如渲染的球体、渐变、色卡），仓库中不放置 Demo 图像。验收时由维护者使用自己的素材。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| DA V2 对二次元立绘的深度偏平，或出现怪异起伏 | 法线三路混合，由 `N_inflate` 兜底；权重开放给用户调节 |
| 单张图片估计光源本身存在歧义 | 结果只作为候选，交给用户确认；显示置信度；灰球预览辅助判断 |
| 反照率与朝向相关（例如朝上的草地、路面）会让 SH 主光偏向这些表面、光色偏向它们的颜色 | 主光颜色投影到普朗克轨迹；方向与可见光源、轮廓、天空梯度交叉合并；用户可在方向球上修正 |
| 原画自带明暗，导致双重阴影 | 比值式增量重光照，并提供强度控制 |
| 颜色匹配过强会让立绘发灰、发暗，失去原画的鲜艳感 | 默认强度偏保守（真实立绘测试表明没有适用于所有素材的默认值）；各项可单独调节；提供前后对比 |
| 大图显存压力 | 预览上限 2048 px，导出分块 |
| 浏览器不支持 WebGPU | 渲染回退到 WebGL2，推理回退到 WASM q4，并提示耗时会变长 |
| 国内访问 Hugging Face 不稳定 | 默认使用魔搭 ModelScope，本站自托管和 Hugging Face 作为备用 |
| 液态玻璃的兼容性和性能 | Chromium 使用折射版，其他浏览器使用毛玻璃；提供“减少特效”开关 |
| 三种设计语言混搭显得割裂 | 按 §6.2 分工，统一 token |
| 手动标定不准，或用户不知道如何标定（M8.5） | 视平线方式适用于任何照片，面板说明视平线是什么；参考形状可以拖到画面各处检查；平行线方式标出消失点、给出不能求解的原因；标定之后随时可以修改 |
| 单张照片的深度重建出的三维场景失真（M8.6） | 明确定位为 2.5D 浮雕：剔除深度跳变处的三角形，提供“回到相机视角”，界面上说明限制 |
| 光晕效果涉及第三方版权（M8.2） | 只借鉴元素构成方式，不使用 Optical Flares 的预设和贴图，元素全部由程序生成 |
| 网格变形拉伸线稿、显得不自然（M8.3） | 定位为透视贴合和轻微调整；随时可以重置 |
| 屏幕空间投影受深度质量影响（M8.7） | 保留平面投影作为可选方式；深度修正画笔（M8.6）可以修正立绘深度 |
