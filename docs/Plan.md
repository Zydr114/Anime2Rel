# Anime2Real 实施计划

> 版本：v1.0（2026-10-16） · 协议：AGPL-3.0-or-later · 验收人：项目维护者本人

## 0. 目标与参考效果

用户上传**真实背景照片**和**二次元立绘**，调整参数后在浏览器本地生成“溶图”（Anime in Real）。

风格参考为 `docs/example.png`，其中包含以下要素：

| 要素 | 示例中的表现 | 对应模块 |
| --- | --- | --- |
| 环境光一致 | 阴天漫射光，人物左上方有大面积高光，暗部偏冷 | 光源分析 + 立绘重光照 |
| 色彩统一 | 人物饱和度被压低，整体偏暖褐色 | 颜色匹配 + 全局调色 |
| 空间感 | 塔身轻微虚化，前景树木压暗 | 深度估计 + 景深 |
| 胶片质感 | 黑位压低、颗粒、左上角丁达尔光束 | 后处理 |

**功能范围**

- ✅ 背景深度估计与光源分析（用户可介入修正）
- ✅ 根据立绘位置自动调整光照和颜色
- ✅ 基于 Depth Anything + WebGPU 的深度估计与景深
- ✅ 基础图像调整（白平衡、曝光、颜色、饱和度等）
- ✅ 后处理（Bloom、胶片颗粒、混色等）
- ❌ 抠图：不提供抠图模型和抠图功能，立绘必须自带透明通道
- ❌ Demo 图像：暂不提供

所有计算都在浏览器本地完成，图片不会上传。站点为纯静态部署。

**数据约定**

- 内部统一使用**线性 sRGB 的 RGBA16F** 纹理，只在输出时编码回 sRGB。
- 预览时长边不超过 2048 px（可配置）；导出用原始分辨率，超过 GPU 纹理上限时分块渲染。
- 深度统一表示为归一化逆深度 `d ∈ [0,1]`，1 表示最近。通过可调映射 `z = 1 / (a·d + b)` 转成伪距离，供景深和点光源衰减使用。

## 3. 核心算法

### 3.1 深度估计（DepthWorker）

1. **背景**：把短边缩放到 518 px（patch size 14 的倍数），用 DA V2 推理得到相对逆深度，再按 1% / 99% 分位数归一化。
2. **立绘**：先把立绘合成到中性灰底上再推理，然后用 alpha 遮罩剔除灰底部分，得到立绘自身的相对起伏。
3. **边缘对齐上采样**：以全分辨率亮度为引导图，用 Fast Guided Filter（He & Sun 2015）把 518 px 的深度放大到工作分辨率，避免景深边缘出现锯齿和光晕。
4. **派生图**：
   - **天空遮罩**：取 d 接近 0、位于画面上部、纹理少的连通区域。
   - **法线图**：对多尺度平滑后的伪深度求 Sobel 梯度，`n = normalize(-k·∂z/∂x, -k·∂z/∂y, 1)`。同时输出置信度，深度不连续处和天空区域降权。
5. **调试视图**：提供深度、法线、天空遮罩三种视图。

### 3.2 光源估计（AnalysisWorker）：生成候选，由用户确认

输入为长边 512 px 的线性背景图、深度、法线和天空遮罩。下面四个估计器各自输出带置信度的候选，再统一融合。

| 估计器 | 方法 | 产出 | 适用场景 |
| --- | --- | --- | --- |
| A. 可见光源检测 | 对 log 亮度建高斯金字塔，在多尺度 DoG 上找局部极大值；对 L > max(P99.5, 0.9·Lmax) 的区域求连通域，并评估面积、紧致度、位于天空还是前景 | 屏幕位置；颜色（取过曝区外环像素）；大小 | 太阳、路灯、窗户、霓虹 |
| B. 球谐（SH）拟合 | 在非天空、法线置信度高的像素上，按 Lambert 假设拟合 2 阶 SH（9 个系数 × RGB）；用 IRLS/Huber 加权最小二乘压低反照率变化的干扰；L1 带的方向作为初值，再用“常数环境光 + 截断余弦方向光”模型在球面上搜索细化（画面法线只覆盖朝向相机的半球，L1 有约 10° 的系统偏差）；置信度 = 方向性（‖L1‖ / L0）× 法线覆盖度 × 拟合优度 | 3D 主光方向、主光强度、环境光（与主光联合拟合的分通道常数）、低频环境光照（供 §3.3 使用）；主光颜色投影到普朗克轨迹，只保留冷暖 | 光源在画面外；阴天 |
| C. 轮廓法（Nillius & Eklundh 2001；Lopez-Moreno et al. 2010） | 在深度不连续处取遮挡轮廓的前景一侧，此处法线落在像平面内；拟合 `I = a + b·(n·l₂D)` | 光在像平面内的方位角 | SH 结果模糊时作补充 |
| D. 天空梯度 | 统计天空区域亮度梯度的主方向 | 太阳的大致方位（可在画外） | 晴天、多云 |

**融合规则**

- C、D 只给出画面内的方位，借用 B 的前后分量（没有 B 时取固定值）补成 3D 方向。
- 方向相差小于 25° 的候选按置信度加权合并（合并后的置信度按“任一成立”累计），保留置信度最高的 3 个。光源强度由 B 的联合拟合给出。
- **阴天判定**：天空占比够大、天空不是夜空、天空亮度变化小、画面反差小、‖L1‖ / L0 小，五项各自打分后相乘。满足且画面里没有可见太阳时标记为“漫射主导”，主光设为来自上方的柔和天空光。
- **光源类型**：
  - 位于天空的候选视为**方向光**，方向是从相机穿过该像素的射线（默认 FOV 60°，可调）。
  - 画面内的灯具视为**点光源**，位置为 `(x, y, z(d))`。

**用户介入**

- 画布上为每个候选显示可拖动的 Gizmo，支持启用/禁用和删除，也可以点击画面添加光源。
- **光照方向球**：在球面上拖动设置方位角和仰角，支持背光（光源在人物后方）。
- 每个光源可调颜色（吸管取色或色温 K）、强度和软硬度。
- **灰球预览**：在立绘位置渲染一个灰色漫反射球，用当前环境光加所有光源照明，方便判断光照是否与背景一致。

M2 实现说明：自动分析在背景的深度结果就绪后进行（长边 512 px，约 0.5 s）；第一次分析的结果直接写入光源列表，“重新分析”会替换现有光源并可撤销。修改视场角后需要重新分析，候选方向才会按新视场角换算。环境光目前是常数（不随法线变化），完整的 SH 保留在分析结果里，M3 再决定是否使用。

### 3.3 立绘融合（随位置自动更新）

立绘的位置、缩放或深度发生变化时，重新计算三项：局部环境光、点光源方向与衰减、局部色彩统计。统计在 Worker 中对低分辨率数据进行，100 ms 防抖。

**(1) 颜色匹配**（`colorMatch` 节点）

1. **照明体适配**：用 Shades-of-Gray（p=6，排除过曝区和天空）或 Gray-Edge 估计背景白点，在 CAT16/Bradford LMS 空间做 von Kries 适配（D65 → 背景白点），强度可调。
2. **影调匹配**：在 Oklab 的 L 通道上，取立绘周围、深度相近的背景区域做加权统计，匹配 P1 / P50 / P99 三个分位点（单调曲线），让黑位和白位一致。
3. **色度匹配**：在 Oklab 的 a/b 通道上做 Reinhard 均值与方差迁移，可选 MKL（Pitié 2007）协方差迁移。提供“肤色保护”。
4. **饱和度收敛**：二次元原画通常比照片更饱和，因此把立绘 Oklch 色度的 P90 收敛到背景的对应分位。

**(2) 法线生成**（预计算后缓存为纹理）

`N = normalize(w₁·N_depth + w₂·N_inflate + w₃·N_detail)`，默认权重 0.5 / 0.4 / 0.1，作为高级参数开放。

- **`N_depth`**：由立绘的 DA V2 深度求得。
- **`N_inflate`**：对 alpha 做精确欧氏距离变换（Felzenszwalb–Huttenlocher），按枕形剖面 `h = r·√(1-(1-t)²)` 膨胀成高度场，再求法线。
- **`N_detail`**：对双边平滑后的亮度做小权重凹凸，并排除线稿，避免线条被浮雕化。

**(3) 增量重光照**（`relight` 节点）

原画本身已经画好了明暗，再整体打一次光会出现双重阴影，所以采用比值式重光照：

```
S(N)       = SH_bg(N)·k_amb·A_local + Σᵢ Cᵢ·Iᵢ·attenᵢ·diffuse(N·Lᵢ)
S_neutral  = 同一公式，光照替换为正面中性光
C_out      = C · lerp(1, S(N) / S_neutral, strength)
           + rim(N,V,L)·C_rim + spec(N,H)·C_spec
```

- **`diffuse` 风格**：写实（wrap Lambert）、柔和（half-Lambert）、赛璐璐（两阶 smoothstep，阈值和柔度可调）。
- **`rim`**：`pow(1 - N·V, p) · saturate(dot(N.xy, L.xy))`，光源在人物后方时自动增强，形成逆光轮廓光。
- **`A_local`**：在背景的大半径模糊 mip 上，按立绘所在位置采样。人物放进阴影区会自动变暗。
- **衰减**：点光源按 2.5D 距离衰减，方向光不衰减。
- **可选**：在立绘高度场上做屏幕空间 AO。

**(4) 边缘与质感融合**（`composite` 节点）

- **Light Wrap**：把模糊后的背景叠加到立绘边缘带（alpha 内缩得到）。
- **边缘软化**：按该深度处背景的清晰度，对 alpha 做 0.5–1 px 羽化。
- **噪声匹配**：在背景平坦区域，用拉普拉斯响应的 MAD 估计噪声 σ，给立绘补上等量噪声。
- **深度遮挡**（默认关闭）：比立绘更近的背景像素以软过渡遮挡立绘，并提供遮罩预览。

M3 实现说明（与上文不同的地方）：

- **统计调度**：没有用固定防抖，而是在计算期间又有变化时，算完后按最新状态再算一次。Worker 一次统计只需几毫秒，所以拖动过程中也会持续更新。立绘深度默认取 alpha 包围盒底边中点处的背景深度，也可以在“前后位置”中手动设置。
- **影调**：P1 和 P50 按强度匹配。P99 不去匹配背景，而是跟随中间调的曝光变化，因为立绘周围的背景里往往没有白色物体。两段斜率都限制在 0.4–2.5。明度变化时 a/b 等比缩放，饱和度保持不变。
- **色度**：Reinhard 均值迁移会把立绘的主色（比如大面积的蓝色衣服）当成色偏去掉，所以改为把周围背景的平均色度按强度叠加到立绘上（“环境色调”），暗部按明度减弱。方差部分交给饱和度收敛：P90 之比先按影调的中间调变化修正，缩放限制在 0.4–1.15。MKL 未实现。
- **重光照的分母**：`S_neutral` 改为当前光照在正面半球上的余弦加权平均 `S_ref`，在立绘中心处由 CPU 计算。这样整体明暗只由影调匹配决定，重光照只带来朝向造成的变化。比值限制在 0–4。环境光使用分析得到的完整二阶 SH，再乘以环境光倍率。
- **`A_local`**：改为“直射光可见度”，取立绘周围与整张背景（非天空）平均亮度之比的平方根，限制在 0.4–1.3，乘在所有光源上。人物站进阴影后直射光变弱、明暗变平；整体变暗交给影调匹配，避免两处重复压暗。
- **轮廓光**：取 `pow(1 − N.z, 2)` 与剪影边缘带两者的较大值，再乘以“朝向光源一侧”和 `saturate(0.3 − 0.7·L.z)`，所以正面光没有轮廓光。边缘带宽度为立绘长边的 2%，由 alpha 的 mip 模糊得到；线稿不参与。混合后的法线在轮廓处往往不够贴近像平面，只靠法线时轮廓光几乎看不出来。
- **高光**：Blinn-Phong，默认强度为 0。屏幕空间 AO 未做。
- **Light Wrap**：边缘带 = alpha × (1 − mip 模糊后的 alpha)，平方后与 mip 模糊后的背景做滤色混合。线稿只保留 30% 的效果，避免描边发灰。
- **边缘软化**：按固定的像素数做十字五点羽化，只作用于 alpha 有变化的地方；暂不按背景清晰度自适应。
- **噪声**：在背景原分辨率上均匀取 4×4 个小块，分别估计后取中位数。在 sRGB 编码空间加三角分布噪声；预览按渲染分辨率缩小 σ。
- **前后对比**只影响预览，导出始终使用融合结果。**深度遮挡**推迟到 M4，与深度合成一起实现。
- **验收结论**（2026-10-18）：算法基本正常工作，默认参数偏保守。光源估计结合各项参数已能调出较好的光照；不存在能适用于所有素材的默认值，默认值保持保守，由用户按素材调节。

### 3.4 深度合成与景深

- **立绘深度** = 放置深度 `z_c` + 立绘自身起伏 × 厚度。`z_c` 默认取背景在立绘 alpha 包围盒底部中点处的深度，代表立绘所站的地面；用户可用“前后位置”滑块调整。
- **对焦**：点击画面即对焦到该点的深度，默认对焦在立绘上。可调参数有光圈、焦外过渡和散景形状。
- **实现分两步**：
  1. **基线**：把合成深度转成 viewZ，交给 three.js `DepthOfFieldNode`。
  2. **目标方案：分层 DOF**。背景按自身的弥散圆（CoC）做深度感知 gather 模糊，近景场和远景场分开处理（参考 Jimenez 2014）；立绘层按自己的 CoC 单独模糊；最后再合成，以消除立绘边缘的光晕和渗色。

M4 实现说明（与上文不同的地方）：

- **跳过基线**：按维护者的决定，没有接入 three.js `DepthOfFieldNode`，直接实现分层 DOF。景深默认开启，光圈较小，对焦在立绘上。
- **弥散圆**：CoC = 光圈 × max(|d − d_focus| − 合焦范围, 0) × 图像长边，d 为归一化逆深度，正值表示近景。薄透镜模型下弥散圆与逆深度差成正比；DA V2 输出的是仿射不变的逆深度，尺度可以并入光圈，偏移在相减时抵消，所以可以直接使用。光圈按“弥散圆相对图像长边”的百分比表示，默认 1%；合焦范围默认 3%。
- **立绘深度**：先把放置深度换算成伪深度 `z_c = 1/(d + 0.1)`，立绘某处的伪深度为 `z_c − (r − r_ref) × scale`，再换回逆深度。r 是立绘自身的深度估计，r_ref 是立绘不透明区域的深度中位数（融合 Worker 计算），所以中位数处正好在放置深度上；`scale = 厚度 × 立绘高度 × z_c / f`，厚度按立绘高度的比例给出，默认 15%。
- **对焦**：自动模式对焦在立绘的放置深度上，焦点标记画在立绘不透明区域的中心。在画布上点到立绘的不透明处时，对焦到立绘该处的起伏深度；点到其他地方时，对焦到背景该点的深度。背景上的对焦点随背景尺寸缩放，更换立绘时立绘上的对焦点恢复为自动。
- **gather**：没有完整实现 Jimenez 2014 的近景场、远景场拆分，改用 Gustafsson《Bokeh depth of field in a single pass》式的单次 gather：
  - 48 个 Vogel 螺旋采样点，可映射为五、六、八边形散景，权重按半径的平方修正。
  - 样本的弥散圆覆盖到当前像素才计入。比当前像素远的样本，弥散圆最多按当前像素的两倍计算，所以模糊的远景不会盖住清晰的近景，模糊的近景可以扩散到清晰的远景上。
  - 采样半径取当前像素所在 16×16 块及周围 3×3 块中弥散圆的最大值；按采样间距选 mip 层级，先做预模糊。
  - 背景层、立绘层、遮挡层各自 gather 后再合成。背景层不包含立绘，立绘层不会采到背景颜色，因此立绘边缘没有光晕和渗色。
- **深度遮挡**（默认关闭）：
  - 遮罩 `m = smoothstep(容差 − 过渡/2, 容差 + 过渡/2, d_bg − d_char)`，在整个立绘矩形内连续计算，透明处按立绘平面的深度算。这样剪影边缘不会因为遮罩被截断而透出立绘的轮廓。
  - 遮挡层 = 背景 × m，按背景的弥散圆模糊，至少做 1 px 模糊用于抗锯齿。
  - 三种方式：
    - **不透明**（默认）：遮挡层直接盖在最上面。
    - **变暗**：在立绘像素上按亮度取较暗的一个，适合树叶、栏杆等细碎的暗色遮挡物；立绘中比遮挡物更暗的部分（如线稿）会透出来，面板中有提示。
    - **正片叠底**：遮挡层与立绘相乘。
  - 遮罩预览只在景深步骤显示。
- **前后对比**改为对比“直接贴上去”（不做融合、景深和遮挡）与当前结果，只影响预览。法线视图同样跳过景深和遮挡。调试视图新增“景深”：合焦处为灰度，近景染蓝、远景染橙。
- **缓存**：背景预处理、块统计和背景景深只在背景、深度、对焦参数或对比状态变化时重绘，拖动立绘时只重绘立绘相关的图层和合成。M3 的拖动测试中步进间隔仍为 17 ms。
- **导出**：以背景原分辨率分配全部图层，最多 7 张全尺寸半浮点渲染目标，其中 3 张带 mipmap。超大图的显存压力留给 M6 的分块导出解决。
- **验收结论**（2026-10-18）：景深部分通过。遮挡按下面的扩展方案实现后重新验收。

M4 遮挡扩展（2026-10-18 与维护者确定）：

- **接地点**：自动估计取立绘不透明区域包围盒底边的中点，但裙摆、披风、特效、坐姿、站在水中等情况下这一点不是脚。现在由用户在画布上拖动接地点，接地点记录在立绘自身的坐标中，可恢复自动。立绘深度改为取接地点附近一小块背景深度的中位数。站在水中时把接地点放在水线处：深度取水线处的水面深度，水位线就是过接地点的水平线（接地点与水位线合并为一个控件）。
- **站立阴影**：
  - **接触阴影**：以接地点为中心的柔和椭圆，宽度取接地点上方立绘的不透明宽度（双脚的跨度），扁度按接地点处的地面朝向估计。
  - **平面投影**：把立绘当作立在接地点上、朝向光源的竖直平面，沿主光源方向投到地面平面上。地面平面由接地点的深度和法线确定，影子长度随光源仰角变化，离脚越远越模糊。
  - 两种阴影都画在背景上，只落在与地面平面深度一致的地方，跟背景一起参与景深。阴影颜色按环境光与直射光之比估计，晴天偏天空色，阴天投影自然消失。立绘底部被裁切（半身像）且接地点为自动时不画阴影。
  - 屏幕空间投影（落在台阶、墙面等不平的表面上）仍在 M8。
- **透明介质与水体**：新增两种遮挡方式。
  - **透明介质**：用于雾、玻璃、薄纱等。按深度对比判断遮挡，结果 = 立绘 × 透过率 + 介质颜色 × (1 − 透过率) + 背景的高频细节；透过率随深度差按指数衰减（Beer–Lambert，即水体着色器中的 depth fade）。介质颜色默认取模糊后的背景。
  - **水体**：水位线以下算作水中，透过率随水下距离衰减；另有水线高光（带波纹起伏的亮边）和折射扰动（水下部分随波纹轻微扭曲）。倒影放到 M8。
- **多区域遮挡**：遮挡物属于背景，所以遮挡区域在背景上划定，不从遮罩中自动拆分（自动拆分的区域在移动立绘时会变化，也不对应物体）。用画笔粗略涂出区域，再用引导滤波吸附到背景的边缘；精确的遮挡边界仍由深度对比决定。最多 4 个区域，每个区域选择自己的遮挡方式和参数，没涂到的地方使用默认方式。笔触以矢量形式记录在文档中，可撤销。

M4 遮挡扩展实现说明（与上文不同的地方）：

- **接地点**：
  - 立绘步骤和景深步骤的画布上都有接地点标记（立绘脚下的短横线和三角）。拖动后变为手动，双击标记或面板中的“恢复自动”回到自动。
  - 接地点按立绘 UV 记录，随立绘移动、缩放、旋转、翻转。
  - 自动模式仍取不透明包围盒底边的中点。
  - 立绘深度取接地点附近一小块背景深度的中位数。
- **站立阴影**（立绘步骤“站立阴影”分组；默认接触阴影 50%、投影 60%）：
  - **地面平面**：过接地点的 2.5D 位置，法线固定为竖直向上，即假设相机水平。没有按计划用接地点处的深度法线：DA V2 的仿射不变深度换成伪深度后，平地的法线明显前倾，光源仰角会被算得很低（合成场景中晴天的 sin 仰角只有约 0.05），投影几乎看不见。
  - **接触阴影**：椭圆宽度取接地点以上包围盒高度 6% 范围内的不透明宽度（双脚的跨度），扁度取视线与地面法线夹角的余弦，限制在 0.1–0.6。
  - **投影**：把立绘当作立在接地点上、朝向光源的竖直平面。地面上沿背离光源方向距接地点 s 处，对应立绘上高 s·tan(仰角) 的位置。离脚越远，按距离取立绘更粗的 mip 层级，影子越模糊。仰角 sin 低于 0.15 时逐渐淡出。
  - **阴影颜色**：挡住主光源（地面上贡献最大的光源）后的光照与全部光照之比，最暗不低于原亮度的 20%。接触阴影在此基础上再遮住 55% 的环境光。
  - **作用范围**：阴影只落在背景深度与地面平面接近的地方，相对深度差 20%–45% 之间逐渐消失，天空上不画。阴影作为乘数图作用在背景上，按背景的弥散圆一起模糊。
  - **不画阴影的情况**：接地点为自动、不透明区域贴着立绘底边、且最下方 1% 的行平均覆盖率超过 45% 时，视为半身像。水体遮挡开启时接地点是水线，同样不画。
- **遮挡方式**：
  - 介质和水体的遮挡强度写在立绘深度图的 g 通道里，合成时与不透明方式一样覆盖立绘，即 遮挡层 + 立绘 × (1 − 遮挡强度)，再叠加背景的高频细节（预处理背景 mip 0 与 mip 2.5 之差）。
  - **透明介质**：遮挡强度 = 在后方 × (1 − 清澈度 × e^(−浑浊度 × 10 × max(Δ − 容差, 0)))，Δ 为背景与立绘的归一化逆深度差。
  - **水体**：遮挡强度 = 在水线下 × (1 − 清澈度 × e^(−浑浊度 × 20 × h / 立绘高度))，h 为水线以下的距离。水体与深度无关，水线是过接地点的水平线，水线随波纹起伏，水线处有一条高光。水下的立绘按波纹偏移采样，形成折射扰动。
  - 新增 **不遮挡** 方式。用于区域时可以排除深度估计出错的地方；用于区域外（默认方式）时，只在画出的区域内遮挡。
  - 选择水体时，画布上画出横跨立绘的水线（浅蓝色虚线）。
- **多区域遮挡**：
  - 面板中的“区域外的遮挡方式”是默认方式，区域列表最多 4 个。选中区域时画布上显示画笔，各区域按颜色着色，正在编辑的区域颜色更深。画笔和橡皮擦的大小按屏幕像素计，一笔一次撤销。
  - 后画的区域覆盖先画的：第 k 个区域的权重 = r_k × Π_{j>k}(1 − r_j)，区域外的权重 = Π(1 − r_j)。合成时每种方式各自计算后按权重混合，变暗、正片叠底单独混合。
  - 笔画按文档坐标记录，更换尺寸不同的背景时按比例缩放。遮罩在不超过 1024 px 的背景缩小图上栅格化，打包成一张 RGBA8 纹理。
  - **边缘吸附**（默认开启，可关闭）：单纯的引导滤波只能柔化边缘，笔画画出界几个像素时移不回背景的边缘。实际做法：
    1. 把笔画边缘两侧各半个笔画半径（2–16 px）的带状区域视为不确定。
    2. 带内每个像素按颜色更接近附近笔画内侧还是外侧的平均颜色归属；内外颜色相近（附近没有边缘）时保持笔画原样。
    3. 最后用半径 2 的彩色引导滤波去噪并保留边缘的过渡。
- **渲染**：WebGPU 每个着色阶段最多 16 张采样纹理，加入阴影和区域纹理后合成着色器超出限制。预览时先把合成结果画到一张渲染目标，再由单独的显示 pass 叠加调试视图、遮罩预览和灰球；导出直接输出合成结果。
- **已知问题**：
  - 每画完一笔，主线程会卡顿约 150 ms（栅格化、吸附和上传）。每张背景第一次吸附时还要多算约 66 ms 的引导图统计量。切换边缘吸附开关会重算全部区域。
  - 投影按乘法压暗背景，落在背景原有阴影里时会重复变暗。
  - 地面平面假设相机水平，俯拍、仰拍明显时影子方向和长度会有偏差。
  - 接触阴影的默认值偏保守，浅色地面上可能需要调高。
- **验收结论**（2026-10-18）：遮挡扩展通过。性能无问题，水体、接触阴影工作正常。M4 完成，进入 M5。

| 色差、暗角 | `ChromaticAberrationNode`；暗角为自定义节点 |
| 胶片颗粒 | 自定义节点：颗粒强度随亮度变化，三通道独立，尺寸可调；按画布像素固定随机种子，保证导出结果与预览一致 |
| 色调映射 | AgX / Khronos PBR Neutral，可关闭 |
| 输出 | 8-bit 导出时加蓝噪声抖动，防止色带 |

**预设**：参数树的 JSON 快照，支持导入和导出。首批四个：阴天胶片（参照示例风格）、黄昏逆光、夜景霓虹、日系清新。

M5 实现方案（2026-10-18 与维护者确定）：

- **三级的分工**：
  - 背景层调整只改背景。立绘的颜色匹配仍按原始照片计算，所以压暗背景可以突出人物；想让两者一起变就用全局调整。
  - 立绘层调整加在融合结果之上。
  - 全局调整作用于合成结果。
- **前后对比**：调色、后期步骤中对比“调色前”（保留融合、景深、遮挡，去掉三级调整、全局调色和后期）与当前结果。其他步骤仍对比“直接贴上去”。
- **预设**：包含三级调整、全局调色和后期的全部参数。套用预设是一次撤销记录。导出的 JSON 内嵌 LUT 数据，可以单独分享。
- **默认值**：全部参数默认中性，色调映射默认关闭，不改参数时输出与 M4 完全一致。背景照片本身已经是显示用的图像，套用 AgX 等色调映射会改变原图的观感，所以只在预设或用户开启时使用。
- **管线**：背景层调整 → 分层景深与遮挡（立绘层调整位于融合之后、立绘景深之前）→ 合成 → 全局基础调整 → 色差 → Bloom、Halation、光束（线性 HDR）→ 暗角 → 色调映射 → 色轮、分离色调、LUT、混色（显示空间）→ 颗粒 → sRGB 编码与蓝噪声抖动。
- **与分辨率无关**：模糊半径、颗粒尺寸、色差、光束长度等都按图像长边的比例定义，预览与导出的观感一致。three.js 的 `BloomNode` 固定使用 5 级 mip，导出大图时光晕范围相对画面会变小，所以改用自己的 mip 金字塔，级数随分辨率变化。
- **局部色调**：高光、阴影和清晰度以对数亮度的快速引导滤波（He & Sun 2015，在 mip 上做盒式均值）为基底，在边缘处不产生光晕。

M5 实现说明（与上文不同的地方）：

- **页面**：调色步骤分为“基础调整”“色彩风格”“预设”三页，基础调整页顶部切换全局、背景、立绘三级；后期步骤是单独的一页。各页都有重置按钮。
- **基础调整**：
  - **顺序**：白平衡与曝光 →（局部：高光、阴影、清晰度）→ 对比度 → 白色、黑色 → HSL → 自然饱和度 → 饱和度 → 曲线 →（局部：锐化）。着色器和 `src/grade/color.ts` 的逐像素版本使用同一组公式和常数，后者用于单元测试。
  - **色温、色调**：参考白点是普朗克轨迹上的 6504 K，两者为 0 时矩阵为单位阵。色温满格为 ±100 mired（+1 约 3940 K，−1 约 18600 K）；色调沿轨迹法线偏移，满格为 0.02（CIE 1960 uv）。
  - **对比度**：在 log2 空间以 18% 中灰为支点，做端点固定的三次 S 形。白点为线性 1.0，黑点在中灰以下 8 档，满格系数 0.5，曲线保持单调。
  - **白色、黑色**：在 sRGB 编码值上分别平移亮部（0.5–1）和暗部（0–0.5），满格为 ±0.2、±0.1。计划中的“局部色调曲线”只用于高光和阴影。
  - **HSL**：8 个色相段的中心取红、橙、黄、绿、青、蓝、紫、品红纯色的 Oklch 色相，相邻段之间平滑过渡。色相满格 ±30°，明度满格 ±30%，接近灰色的颜色不调明度。自然饱和度对低色度的颜色作用更强，并对 Oklch 色相 55° 附近的肤色减弱 70%。
  - **曲线**：在编码值上计算，主曲线先于单通道曲线；单调三次样条烘焙成 256 点的查找表，超出 1 的值按末端斜率延伸。
  - **局部调整**：
    - 先把这一级的输入画成 log2 亮度的 mip 金字塔，再在 1/4 分辨率上算两个尺度的快速引导滤波系数。高光、阴影的基底半径为长边的 1/24、ε = 0.25，清晰度为 1/96、ε = 0.12。
    - 高光、阴影平移基底，满格分别为 1 档和 2 档；清晰度放大中尺度细节，中间调全强度；锐化是半径为长边 1/2000（至少 1 px）的亮度 USM。
    - 三级依次渲染，共用这两张纹理；没有局部调整时不分配、不计算。立绘层按不透明度加权，透明处退化为逐像素调整。
- **色彩风格**：
  - **色轮**：在编码值上逐通道计算 e' = (gain · (e + lift · (1 − e)))^(1/gamma)。每个色轮的亮度给出三个通道相同的分量；偏色方向取该 Oklch 色相在编码值空间中亮度为 0 的方向。
  - **分离色调**：在 Oklab 中按亮度给暗部、亮部加上 (a, b) 偏移，不改变亮度。满格色度为 0.06，过渡半宽 0.3，平衡满格时过渡中心移动 0.25。L < 0.15 时暗部色调逐渐减弱，纯黑保持中性。
  - **LUT**：没有用 `Lut3DNode`，在终处理 pass 中用半精度三维纹理按 sRGB 编码值查表，超出定义域的值被裁剪。一维 LUT 展开为 33³，三维 LUT 的边长上限为 129。LUT 数据按内容哈希登记在内存中，文档只保存 id、文件名和强度。
  - **混色层**：最多 4 层，可上下移动；纯色，或按底图亮度取色的 2–3 色渐变映射。实现了 W3C Compositing and Blending Level 1 的全部 16 种混合模式（计划列出 8 种），在编码值上计算。亮度蒙版的边缘柔化半宽为 0.1。
- **后期**（不使用 three.js 的 `BloomNode`、`radialBlur` 和 `ChromaticAberrationNode`）：
  - **Bloom 与 Halation**：
    - 共用一套 8 级 mip 金字塔。第 0 级长边固定为 1024 px，各级尺寸只由画面比例决定，所以预览和导出的光晕范围相同。
    - 预滤波用 Jimenez 2014 的 13 点降采样。Bloom 对最大通道取软阈值，Halation 对亮度取阈值，结果存在 alpha 通道。
    - 上采样为 up_k = mix(d_k, tent(up_{k+1}), 散射)，半径换算为散射 0.4–0.95。
    - Halation 在第 0 级只保留扩散到亮部外侧的部分（tent − 原值），所以红晕只出现在高光边缘，不会把整片高光染色。
  - **丁达尔光束**：
    - 遮罩 = 亮度软阈值 × 天空权重 × (1 − 立绘不透明度) × 1/(1 + (d/0.3)²)，d 为到光源的距离。天空权重在有深度、且开启“只让天空发光”时取天空遮罩，否则为 1。
    - 向光源方向做 3 次、每次 8 个样本的径向模糊。样本间距按指数分布，每次放大 8 倍；贡献随距离按指数衰减。光束长度按长边的比例定义。
    - 光源默认自动选择：优先方向光，其次按强度，跳过在相机后方的光源；也可以手动指定。没有可用光源时光束不生效，面板中给出提示。
  - **色差**：红、蓝通道按到画面中心的距离向相反方向缩放，满格时边缘处相差 ±1.5%。7 个采样从蓝到红平滑过渡，每个通道的权重之和为 1，不会出现分离的三重影。
  - **暗角**：曝光乘以 2^(档数 × smoothstep(内, 外, r))，r 以画面角落为 1；满格 ±2 档，负值压暗，正值提亮。中点和羽化决定内外半径。
  - **颗粒**：
    - 按长边比例划分网格，格子为长边的 1/3000–1/500。每个格点三个通道各取一个随机数，格点之间平滑插值，并按方差归一化，彩色程度在单色和三通道独立之间混合。
    - 颗粒加在编码值上，中间调最强，暗部和亮部为 35%。
    - 网格由文档坐标决定，预览与导出的颗粒图案一致，导出大图时颗粒随画面一起放大。颗粒小于一个像素时按尺寸减弱，使缩小的预览与导出图缩小后的观感一致。
  - **色调映射**：使用 three.js 的 AgX 和 Khronos PBR Neutral，默认关闭。
  - **抖动**：没有用蓝噪声纹理，改用 R2 低差异序列，在编码值上加 ±0.5 LSB 的抖动，预览与导出都有。只在有调色或后期参数生效时开启，所以不改参数时输出与 M4 一致。
- **预设**：
  - 在调色步骤的“预设”页，包括四个内置预设、本次会话中导入的预设、预设文件的导入导出，以及“清除调色与后期”。与当前参数一致的预设显示为选中。
  - 内置预设只调整全局一级。“阴天胶片”参照 `docs/example.png` 的风格：暖褐色调，绿色压暗并偏红褐，黑位压低，亮部略收，带颗粒和暗角。
  - 套用预设时替换三级调整、色彩风格和后期参数，是一次撤销记录。光束的光源与画面有关，不随预设保存，套用时保留当前的选择。
  - 预设文件是 JSON，使用中的 LUT 以 base64（float32，小端）内嵌，导入时重新登记。导入的内容逐字段检查类型并限制在界面允许的范围内，缺少或无效的字段取默认值，内置预设也经过同样的处理。导入的预设只在本次打开页面期间保留，持久化留给 M6 的工程保存。
- **渲染**：
  - 全局调整之后是一个终处理 pass，依次做色差 → Bloom、Halation → 光束 → 暗角 → 色调映射 → 色彩风格 → 颗粒。Bloom 和光束只在强度大于 0 时渲染。
  - TSL 的 `select` 会生成 if/else，两个分支共用的子表达式只在第一个分支里构建，另一个分支会读到未初始化的变量，导致画面全黑。终处理 pass 因此改用 `Fn` + `If` 组织，代码中有注释说明。
- **已知问题**：
  - Neutral 色调映射的趾部会把很暗的颜色压黑，并加重暗部的偏色。这是 Khronos PBR Neutral 本身的设计，夜景照片上很明显。内置预设都没有开启色调映射。
  - 光束只支持一个光源。
  - 抖动用的是 R2 序列，是蓝噪声的近似，极平滑的渐变上仍可能看到很弱的规则纹理。
  - 内置预设只在程序生成的场景上调过，在真实照片上的效果需要维护者验收时评估。
- **验收结论**（2026-10-19）：通过。维护者测试后认为效果很好，暂无需要改进的地方。M5 完成。

## 4. 用户流程

1. **素材**：拖拽、粘贴或选择背景和立绘。空状态只显示上传引导，不提供示例图。立绘没有透明区域时提示“请上传透明 PNG/WebP”。背景主色会驱动动态主题。
2. **深度**：首次使用时加载模型（显示进度，可切换模型源），然后自动推理；可查看深度、法线和天空遮罩。
3. **光源**：查看候选光源，用 Gizmo、方向球和灰球预览进行确认或修改。
4. **立绘**：拖拽、缩放、旋转、翻转、调整前后位置；调节颜色匹配、重光照和边缘融合的强度，实时预览。
5. **景深**：对焦、光圈、深度遮挡。
6. **调色**：三级基础调整、色轮、LUT、混色。
7. **后期**：Bloom、Halation、光束、颗粒、暗角、色差。
8. **导出**：选择格式、质量、分辨率倍率；也可以把参数和素材保存为工程（IndexedDB 或 `.a2r` 文件）。

任何步骤都可以使用：前后对比滑块、撤销/重做、调试视图切换。

## 5. 渲染与性能

- **脏标记重算**：深度、法线、统计只在素材或立绘位置变化时更新；调节滑块只重跑下游 pass。
- **两档分辨率**：交互过程中降到 50% 分辨率，停止操作 200 ms 后渲染完整预览。
- **纹理预算**：一张 12.6 MP 的 RGBA16F 纹理约占 100 MB，因此预览上限为 2048 px。导出时按 `maxTextureDimension2D` 分块渲染，相邻分块留出等于最大模糊半径的重叠区。
- **推理隔离**：推理在独立 Worker 中进行，模型只加载一次。
- **能力探测**：检测 WebGPU、`shader-f16` 支持情况、`maxTextureDimension2D` 等，结果显示在“关于”页面中。

## 6. UI 设计

### 6.1 布局

**PC 优先**：面向 1280 px 以上宽度，鼠标加键盘操作，支持快捷键。

- **画布**：全屏，背景用深色中性灰，避免干扰色彩判断。
- **左侧**：mdui `navigation-rail`，列出 8 个步骤。
- **右侧**：液态玻璃浮动检查器，内部使用 mdui 的 slider、switch、segmented-button，可折叠。
- **底部**：基于 Magic UI `Dock` 的液态玻璃工具栏，包含缩放、前后对比、撤销、调试视图、导出。
- **首屏**：`BlurFade` + 衬线体标题（Instrument Serif，暖灰底色配香槟金强调色）；上传区加 `BorderBeam`；`ShimmerButton` 作为主按钮；模型加载时用 `AnimatedBeam` 展示“图像 → 深度 → 光源”的处理流程。

**移动端（次要目标）**：检查器改为底部抽屉，导航改为底部导航；预览上限降到 1024 px；支持双指缩放和旋转立绘；液态玻璃降级为毛玻璃。

### 6.2 设计语言整合

为避免三种风格混在一起显得割裂，按以下分工使用：

- **mdui**：负责所有交互控件，统一采用 Material 3 的行为和可访问性。
- **液态玻璃**：作为面板容器的材质，替代 M3 的 surface container。
- **Magic UI**：只用于动效和装饰，不承担表单交互。
- **主题色**：把 mdui 的 `--mdui-color-*` 变量映射为 Tailwind v4 的 `@theme` token，让动态主题色同时作用于三者。

### 6.3 液态玻璃

- **Chromium**：使用 SVG `feDisplacementMap` 配合 `backdrop-filter: url(#…)`。位移图在 canvas 上一次性生成：先求超椭圆圆角矩形的 SDF，再按 Snell 定律计算折射偏移，RGB 三通道使用不同偏移量以形成色散。数学参考 iyinchao/liquid-glass-studio（MIT）。
- **Firefox / Safari**：回退为 `backdrop-filter: blur() saturate()`，加内高光描边和菲涅尔渐变边框。
- **开关**：设置中提供“减少特效”，并遵循 `prefers-reduced-motion` 和 `prefers-reduced-transparency`。

## 8. 验收流程

1. **交付**：每个阶段完成后，开发方提交一份验收说明，包括：
   - 本阶段完成的内容，以及与计划的差异
   - 启动或部署方式
   - 逐条可操作的验收清单
   - 开发期自测记录（单测结果、已测浏览器）
   - 已知问题
2. **验收**：维护者本人按验收清单执行，给出“通过”或“不通过”以及具体意见。开发方不自行宣布某个阶段已通过验收。
3. **推进**：阶段通过后才进入下一阶段。未通过的项目在当前阶段修复后重新提交验收。
4. **测试图像**：开发期的自动化测试只使用程序生成的合成图像（例如渲染的球体、渐变、色卡），仓库中不放置 Demo 图像。验收时由维护者使用自己的素材。

## 9. 风险与对策

| 风险 | 对策 |
| --- | --- |
| DA V2 对二次元立绘的深度偏平，或出现怪异起伏 | 法线三路混合，由 `N_inflate` 兜底；权重开放给用户调节 |
| 单张图片估计光源本身存在歧义 | 结果只作为候选，交给用户确认；显示置信度；灰球预览辅助判断 |
| 反照率与朝向相关（例如朝上的草地、路面）会让 SH 主光偏向这些表面、光色偏向它们的颜色 | 主光颜色投影到普朗克轨迹；方向与可见光源、轮廓、天空梯度交叉合并；用户可在方向球上修正 |
| 原画自带明暗，导致双重阴影 | 比值式增量重光照，并提供强度控制 |
| 颜色匹配过强会让立绘发灰、发暗，失去原画的鲜艳感 | 默认强度偏保守（真实立绘测试表明没有适用于所有素材的默认值）；各项可单独调节；提供前后对比 |
| 大图显存压力 | 预览上限 2048 px，导出分块 |
| 浏览器不支持 WebGPU | 渲染回退到 WebGL2，推理回退到 WASM q4，并提示耗时会变长 |
| 国内访问 Hugging Face 不稳定 | 默认自托管模型，魔搭 ModelScope 作为备用 |
| 液态玻璃的兼容性和性能 | Chromium 使用折射版，其他浏览器使用毛玻璃；提供“减少特效”开关 |
| 三种设计语言混搭显得割裂 | 按 §6.2 分工，统一 token |
